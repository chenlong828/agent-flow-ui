## 适用场景

你正在分析缺陷、需求或审核意见，需要先回答「该从哪个服务入口进去看」，才能继续规划排查、设计用例或评估影响面。本技能把功能号、服务名或一段业务描述，落到系统流程目录、业务目录和一组入口卡片上，产出一份可回指、可复核的定位结果。

输入分两种形态，判据只有一条：手上有没有能直接打开卡片的标识。

- **直定形态**：已有七位功能号，或已有 LS_ 开头的服务名（中文名与英文文件名都算）。此时只打开对应的那张卡，不拆业务词，不对业务流程，路径留空。
- **收卡形态**：输入是业务别名、功能名、交易方向或系统流程名。此时三份索引都要跑，流程与业务只贡献路径，入口仍然只从卡片索引取。

产出物是一份定位契约：`paths` 记流程与业务目录的位置，`entries` 记入口卡片，`miss` 记对不上时的定性。下游按这份契约继续，所以每条入口都要带项目，每条路径都要能按记录的位置直接打开。

触发词：功能号定位、入口定位、业务词定位、按卡直定、按词收卡、流程目录、服务入口卡片、V 卡。

不适用：判断根因、读具体函数的实现、查交易所字段或外部接口规格、推演规则条款影响。本技能只到服务入口，往下的腿级清单、调用链与影响面归代码资产侧。

## 执行步骤

### 第一步：判形态，只走一条路

| 判据 | 形态 | 走哪套细则 | 产出侧重 |
|---|---|---|---|
| 有七位功能号 | 直定 | 第二步 | 一张卡的 `entries`，`paths` 为空 |
| 有 LS_ 服务名或英文文件名 | 直定 | 第二步 | 同上，可能命中多张卡 |
| 其余任何输入 | 收卡 | 第三至七步 | 路径加入口卡片，三份索引都跑 |

判形态时不要发挥：没有功能号或服务名，不要因为某个词像功能名就去猜一个号；收卡形态里也不要先判定输入是流程、业务还是功能，三份索引一起跑正是为了避免先分类漏线索。

### 第二步：直定形态怎么走

先把功能号送进卡片索引做全项目检索。功能号不要直接丢给源码索引，因为源码索引不带项目参数时会有缺省项目，等于悄悄锁死一个假设：

```bash
kg_query_vcard.py --id <七位功能号>
kg_query_vcard.py --name "<LS_服务名或英文文件名>"
```

拿到卡片之后，才用卡片上已写明的项目去核对源码索引：

```bash
code_index.py --id <七位功能号> --project <卡片上的项目>
```

顺序不能颠倒：先假设项目再查卡片，会把别的项目里的同号功能一起捞出来，项目假设错了还会得到一份看着自洽、实际错位的清单。调用任何脚本前先看 `--help`。

### 第三步：收卡形态的三份索引

三份索引各有脚本，不要合并成一条命令，职责完全不同：

| 索引 | 贡献什么 | 明确不贡献什么 |
|---|---|---|
| 系统流程索引 | 流程目录与说明文件位置，写进 `paths` | 不贡献入口，不打开流程正文 |
| 业务语义索引 | 业务别名命中的业务目录，写进 `paths`，并用来圈定卡片范围 | 不贡献入口，不把卡片的业务线字段当业务目录 |
| 卡片索引 | `entries` 的唯一来源 | 不往 `paths` 里写目录 |

**拆实词。** 挑出问句里的名词、动词、方向词；「不对」「异常」「失败」这类评价词不查，它们只表达好坏判断，不是系统里的实体。同一实词可同时送三份索引，不必先猜类别。

**查系统流程。** 命中就把流程目录写进 `paths`，带类型标记与说明文件位置。到此为止：不打开流程正文，不从流程文档或机制说明里抄功能号，命中的流程名也不再单独拿去铺全库。

**查业务语义。** 这里只有业务名和别名。命中时看返回的业务目录，带边界提示时用提示的去向目录，不回原目录找。写入 `paths` 后，这个目录就是下一步卡片检索的范围。头寸、资讯导入不是业务，查不到属正常，不要手工补进去，也不要改去流程正文抽卡。

**查卡片。** 有业务目录时在目录内用动词或方向收卡；`--dir` 只查卡片索引，按目录前缀匹配，默认已排除归档目录与失效卡。目录内收不到，再按业务名或环节词查源码侧入口清单，每个功能号回卡片索引再查一次：图谱已有就改挂那张卡，源码有入口而图谱没这张卡才提补卡。没有业务目录，或问句里还有没用上的方向、服务名、功能名片段时，才查全库，命中多张只留方向或目录对得上问句实词的卡。单独的「查询」「处理」不当全库关键词，要和对象拼成片段再查，例如「可用数量查询」。

### 第四步：入口全集与候选排序

`entries` 只来自卡片索引，一条等于一个项目下的一个功能号。合并按判据执行：

| 情况 | 做法 |
|---|---|
| 同一项目同一功能号，多个市场各登记一条 | 合并成一条，市场差异进说明 |
| 同一功能号出现在不同项目 | 每个项目各留一条，都带项目 |
| 同一英文服务名对应多个功能号 | 每张卡各留一条，不因名字相同就合并 |

排序与取舍：先收业务目录内的卡，后收全库的卡；同一来源内按卡片方向与问句实词的贴合程度排；两处命中同一项目同一功能号时合并，保留先写入的方向与文件位置。全库检索默认只取前若干条，超出说明实词不够，应补实词而非加大条数。归档与失效卡不计入候选。

### 第五步：卡片字段怎么读

| 字段 | 含义 | 使用要求 |
|---|---|---|
| 功能号 | 七位编号，入口主键之一 | 原样写出，不改写、不补零 |
| 服务名 | LS_ 形式的中文名或英文文件名 | 直定时是检索入口，收卡时是回指线索 |
| 项目 | 这张卡属于哪个项目 | 每条入口都必须带 |
| 方向或「做什么」 | 卡片上对该入口的一句业务描述 | 取原文，不自己概括成更顺的一句 |
| 目录与文件名 | 卡片文件所在目录与文件名 | 两者拼成回指位置 |
| 失效标记 | 该卡是否仍是现役 | 为真即排除，不作为入口 |

回指位置要原样搬运：复核时按它直接打开这张卡，不必再回全库搜索。

### 第六步：路径回指

`paths` 只记位置，顺序先系统流程、后业务。每条写清类型、目录以及该目录下说明文件的位置；流程索引一并带回了流程文件位置就写上，没有就省略。`paths` 里不放功能号、不放卡片，它是位置清单而非入口清单。

直定形态 `paths` 是空数组。收卡形态下，卡片检索这一步不往 `paths` 写目录，即使检索的目录正是从业务路径来的。

### 第七步：对不上时的定性

两种形态共用一张表，从上往下取第一条适用的就停，不要连试到编出一个项目为止。

| 情况 | 定性 | 做法 |
|---|---|---|
| 业务目录里问句的环节对不上，但同目录另一张卡对得上 | 改挂过（`retargeted`） | 只改一次，入口用改对的卡，不从流程正文改挂 |
| 卡片实际在别的目录 | 改挂（`miss` 留空） | 改挂到那张卡，不提补卡 |
| 业务材料已写明该环节没有对外服务 | 已知缺口（`known_gap`） | 按已知缺口记录，不从流程正文推断 |
| 业务目录里源码有入口、图谱没这张卡 | 提议补卡（`propose_v`） | 记录提议，不改业务流程文档，不从流程正文发起 |
| 有动词或方向，但没有流程路径、没有业务路径、也没有现役卡 | 未找到（`not_found`） | 如实记录未找到 |
| 没有动词也没有方向，三份索引都没命中 | 无动词（`no_verb`） | 如实记录，不对业务目录或全库铺开 |

没有卡片时 `entries` 留空数组，不要填项目占位。

### 第八步：交给代码侧

定位完成不等于可以直接翻代码，分工是固定的：

| 步骤 | 归属 | 做什么 |
|---|---|---|
| 功能号或业务词到服务入口与卡片 | 本技能 | 跑三份索引，产出路径与入口 |
| 服务入口到腿级清单 | 代码资产侧 | 按入口编号取腿与函数清单 |
| 腿或函数到调用链、影响面与文件内行号 | 代码资产侧 | 按清单追调用链，不猜仓库根，在已确定的文件里查行号 |

判据只有一句：允许在已知文件内定位行号，禁止在全库范围搜索找文件。前者是取证深化，后者是用搜索代替定位。所以不要在源码库盲扫功能号、服务名、表名；索引没命中就按上一步定性，不得转搜索兜底，也不要凭印象跳过索引打开源码。

## 示例

**示例一：功能号直定，同一编号跨两个项目。** 输入只有七位功能号 `1000123`。先查卡片索引，返回两张卡，分属项目甲与项目乙。源码索引的核对拆成两次，各自带卡片上的项目。最终 `entries` 两条，项目字段分别写甲和乙，方向取卡片原文，回指位置取各自目录与文件名，`paths` 与 `miss` 留空。

**示例二：服务名直定，英文名命中两张卡。** 输入是英文服务文件名，没有功能号。用服务名查卡片索引，返回两个不同功能号的两张卡。此时不要挑一张看起来更像的，两张都留，各自带功能号与项目。若其中一张所在目录已归档或已标失效，只留另一张，并写清排除了哪一张。

**示例三：业务词收卡，三份索引交叉。** 输入是「可用数量的查询结果和预期不一致」。去掉评价词，留下「可用数量」「查询」两个实词；「查询」太泛，和对象拼成「可用数量查询」再查。系统流程索引没命中，这一步不写 `paths`，也不因此结束。业务语义索引命中一个业务目录，写入 `paths`，该目录同时成为卡片检索范围。目录内用动词「查询」收卡，收到两张方向贴合的卡，进入 `entries`。随后发现「可用数量」没被业务别名覆盖，再查一次全库，只留方向或目录对得上的那几张，再按项目与功能号合并。

**示例四：流程词只落路径。** 输入是「日初调用时的处理顺序」，系统流程索引命中一个流程目录，把目录与说明文件位置写进 `paths` 并记类型；这里停住，不打开正文找功能号，也不把流程名拿去铺全库。若业务目录内按动词收不到卡，改按业务名查源码侧入口，源码有入口而图谱没这张卡就记提议补卡，不改业务流程文档。

## 脚本

本技能没有自带执行脚本，全部依靠索引侧查询脚本。下面是示意名，实际以当前包装备的脚本为准，调用前先看 `--help`。

| 脚本 | 只查什么 | 典型用法 |
|---|---|---|
| `kg_query_vcard.py` | 卡片索引 | `--id <功能号>`、`--name "<服务名>"`、`--dir <业务目录> "<动词或方向>"` |
| `kg_query_business.py` | 业务语义索引 | `<实词> --json` |
| `kg_query_flow.py` | 系统流程索引 | `<实词> --json` |
| `code_index.py` | 源码索引，用于核对与补卡判断 | `--id <功能号> --project <项目>` |

三份索引各一条命令，不要拼成一条。全库检索给返回条数一个上限，默认值就够，不要为了多收把上限调大。

输出契约形状如下，调用方按自己的字段体系映射，本技能不定义下游领域字段：

```json
{
  "mode": "word",
  "paths": [
    {"kind": "system_flow", "dir": "", "readme": ""},
    {"kind": "business", "dir": "", "readme": ""}
  ],
  "entries": [
    {"func_id": "", "ls_name": "", "project": "", "place": "", "map_ref": ""}
  ],
  "miss": null,
  "reason": ""
}
```

`mode` 只有两个取值，直定写 `card`，收卡写 `word`。直定形态 `paths` 为空数组；收卡形态按系统流程在前、业务在后排列。`entries` 没有卡片时是空数组，不是 `null`。`miss` 在对不上时取前述定性之一，其余为 `null`。调用方要求落盘时按契约校验写入指定路径，校验命令退出码为 0 才算完成。

## 完成验证

- [ ] 形态判据成立：有功能号或服务名走直定，其余走收卡，只走了一条。
- [ ] 直定形态先查卡片拿到项目，再带项目核对源码索引，顺序没颠倒。
- [ ] 收卡形态三份索引都跑过，空结果已忽略，没有因某一份没命中就提前结束。
- [ ] `paths` 只有目录与说明文件位置，没有功能号，顺序是先流程后业务。
- [ ] `entries` 全部来自卡片索引，没有一条从流程正文里抄来。
- [ ] 每条入口都带项目，跨项目同号已分列，同项目同号的多市场登记已合并。
- [ ] 回指位置是目录加文件名的原样组合，可以直接打开。
- [ ] `miss` 取的是第一条适用项，没有为了凑出一个项目而连试。
- [ ] 没有对源码库盲扫，索引未命中时已按定性处理。

## 常见踩坑

- **只按裸功能号下结论。** 反例：查到功能号就写一条入口，不写项目；同一编号在不同项目是不同入口，缺了项目下游无从判断。做法是每条入口都带项目，跨项目同号各列一条。
- **把流程正文当入口来源。** 反例：查不到卡就翻流程说明文档，把里面提到的功能号抄进 `entries`；文档一改，清单就失真。做法是流程只写 `paths`，入口只从卡片索引取。
- **拿流程名去铺全库。** 反例：命中流程目录后，又把流程名单独丢进卡片索引全库检索，收回一堆不相关的卡。做法是已命中流程的词不再单独铺全库，问句其余实词仍要查。
- **目录里没收到卡就宣布没有入口。** 反例：业务目录内检索为空，直接写未找到；这只说明目录内的卡对不上，还有业务名查源码入口、全库片段两条路。做法是走完再定性。
- **用全库检索代替实词打磨。** 反例：全库命中几十张卡，就把返回上限调大全部塞进 `entries`；这已不是定位而是铺库。做法是回头补实词，或只留方向与目录对得上问句的卡。
- **索引没命中就转搜索兜底。** 反例：卡片索引没结果，直接在源码库搜功能号、服务名、表名，扫几轮才找到文件；这是用搜索代替定位。做法是按定性记录未命中，交代码资产侧从入口往下走。
- **跳过索引凭印象打开源码。** 反例：觉得「这个功能我熟」，不查索引直接打开某个文件；入口必须以索引结果为准，否则调用链与影响面都建在未验证的假设上。做法是先定入口，再在已确定文件内取证。
- **把回指位置写成业务名。** 反例：回指位置只写「某业务某模块」，没有目录与文件名，下游按它打不开任何文件。做法是原样搬运目录与文件名。
