## 适用场景

你要用真实流量或生产样本做回放验证，但原始数据不能直接进测试环境：里面有客户身份、账号、金额、联系方式，格式也可能与目标环境不一致。你要在回放前完成采样、清洗、脱敏、对账，回放后完成还原与销毁。

输入：样本来源与授权范围、目标环境、字段说明。输出：可回放的清洗数据、脱敏映射、对账结果、回放记录、还原与销毁证明。

触发词：回放、流量回放、样本清洗、脱敏、对账、数据还原。

不适用：已经脱敏的离线样例；生产数据直接灌库；没有授权的数据导出。

## 执行步骤

### 第一步：确认授权与范围

先确认三件事：数据来源有授权、使用范围仅限本次回放、保留期限明确。三者缺一不做。

范围写清：哪些表、哪些字段、时间窗、样本量。范围外的数据不采，避免把无关敏感信息带进测试环境。

### 第二步：采样与快照

按时间窗与业务条件采样，保留原始快照的校验和（条数、主键哈希、金额汇总）。快照只读存放，后续所有清洗都基于快照，不直接改源数据。

样本要能覆盖主流程与关键分支：正常、边界、异常各留一部分。全取正常样本，回放只能证明「顺利时没问题」。

### 第三步：清洗

清洗按固定顺序：

1. 格式归一：编码、日期格式、金额精度、枚举值统一到目标环境口径。
2. 去重：按业务主键去重，保留最早或最新一条，规则写清。
3. 补全：目标环境必填但源数据缺失的字段，用默认值或映射补齐，并记录补了哪些。
4. 时间偏移：回放需要「当天」语义时，整体平移时间，保持相对间隔不变。
5. 过滤：范围外、测试账号、系统内部记录剔除，剔除清单留档。

清洗不改业务语义：金额、数量、状态这些影响结果的字段，只做格式转换，不做「看起来合理」的修改。

### 第四步：脱敏

脱敏要保结构、保关联、可还原：

| 字段类 | 处理 | 要求 |
|---|---|---|
| 姓名 | 替换为固定假名 | 同一人全流程一致 |
| 证件号 | 保留前几位与长度，其余掩码 | 不保留校验位 |
| 手机号 | 中间四位掩码或替换号段 | 不指向真实号码 |
| 资金账号/股东号 | 按映射表替换 | 跨表关联保持一致 |
| 地址 | 保留省市，详细地址替换 | 不保留门牌 |
| 金额 | 保留数量级，按比例缩放 | 汇总仍可对账 |

映射表单独存放、加密、限权访问，不跟数据放一起。脱敏后做残留扫描：用原值关键词、正则、抽样人工检查三种方式确认无残留。

#### 脱敏算法与映射表结构

映射表要同时支撑还原、对账、审计，至少含五列：

| 列 | 含义 | 要求 |
|---|---|---|
| batch_id | 批次号 | 与样本批次一一对应 |
| field | 字段 | 表名.字段，避免同名混淆 |
| src_digest | 源值摘要 | 带盐哈希，不落明文 |
| masked_value | 脱敏值 | 实际写入测试环境的值 |
| algo | 算法 | 假名表、格式保持加密、分桶 |

算法按字段选：姓名用固定假名表，可读性好；证件号与账号用格式保持加密，长度与校验规则不变，下游校验不报错；金额用比例缩放，分布形态保留，汇总仍能对上。

跨表关联以主体键作为算法输入，而不是各表自己的账号，账户、委托、流水替换后天然一致。每批次换独立盐值，同一源值跨批次结果不同，避免交叉比对反推原值。

### 第五步：对账

回放前对账四件：条数、主键集合、金额汇总、关键字段分布。四项与快照一致才算清洗成功；不一致要定位到哪一步造成的，不带差异回放。

回放后再对一次：写入条数、成功失败比、金额汇总、异常记录。两次对账结果都写进报告。

#### 对账口径与 SQL 示例

四项口径要写成可执行的查询，不靠肉眼：

```sql
-- 条数与金额，金额统一用整数分
SELECT count(*) AS cnt, coalesce(sum(amount_cent), 0) AS amt
FROM clean_order
WHERE biz_date >= '2026-10-31' AND biz_date < '2026-11-01';

-- 双向主键差集，确认没有多也没有少
SELECT id FROM snapshot_order EXCEPT SELECT id FROM clean_order;
```

三点约束：金额用整数分，不用浮点求和；时间窗统一半开区间，避免边界重复或漏采；聚合前确认空表返回 0 而不是 NULL。条数、主键、金额三项零容忍，字段分布允许偏差但要在报告里写明原因。

### 第六步：回放

回放守四条：按业务顺序、接口幂等、环境隔离、限速。

- 顺序：有依赖的报文按原顺序回放，乱序会导致状态错乱。
- 幂等：重复回放不产生重复入账，用幂等键或先清后放。
- 隔离：回放环境独立，不与共享测试环境混跑。
- 限速：按目标环境容量控制速率，压垮环境会让结果不可信。

失败的报文单独记录，可重放；重放仍失败则归类为数据问题或环境问题，不混入业务结论。

#### 回放调度与失败重放

调度分两层：分片按主键哈希，片内按业务时间戳排序，片间并行；同一主体的报文必须串行，避免状态竞争。

限速用令牌桶，起步压到目标容量的三成，观察错误率与延迟再阶梯上调；错误率连续一分钟超过阈值就降速或暂停，而不是硬扛。

失败报文进死信清单，记原始报文号、失败原因、重试次数。指数退避重试三次，仍失败则归类为数据问题或环境问题。重放沿用原批次号与报文序号，幂等键不变，避免重放变成重复入账。

中断后按位点续放：位点记时间戳加主键，从断点继续，不从头再来。

### 第七步：还原与销毁

回放结束按约定还原：清理写入数据、恢复被修改的配置、停用临时账号。还原后跑一次对账，确认无残留。

样本与映射表按保留期限销毁或归档；销毁要有记录（谁、何时、什么范围）。未到期的样本加密存放，不放在个人目录。

#### 数据生命周期与销毁审计

生命周期五个节点：采样、清洗、回放、保留、销毁，每个节点记时间、责任人、数据位置。

销毁范围要列全：数据库行、对象存储、本地导出文件、中间结果、日志、备份。逻辑删除不算销毁，要么物理删除，要么销毁加密密钥使数据不可解。

销毁留三样证据：清单（对象、位置、条数、方式）、执行人与见证人、销毁后抽验结果（用原值关键词再查一次，确认为零命中）。

保留期限落到工单或日历提醒，到期未销毁按违规处理。

## 示例

**示例一：委托流量回放**

采样一天委托报文 5,000 条，快照校验和记录。清洗：统一日期格式、按委托号去重、补全市场代码。脱敏：资金账号与股东号按映射替换，姓名替换假名。对账：条数 5,000、金额汇总一致、主键集合一致。回放：按原顺序、限速 100 条每秒。回放后写入 5,000 条、失败 3 条（数据缺失），单独列出。结束清理写入数据，对账归零。

**示例二：脱敏残留**

脱敏后扫描发现一条备注字段含真实手机号。定位到清洗规则只覆盖了结构化字段，没覆盖自由文本。补正则替换后重扫通过。结论：自由文本必须单独扫描。

**示例三：对账不一致**

清洗后条数少 12 条。逐项定位发现去重规则把同一委托的多次回报当成重复。修正规则：按「委托号 + 回报序号」去重，条数恢复一致后再回放。

**示例四：完整对账报告**

| 口径 | 快照 | 清洗后 | 回放写入 | 差异 | 结论 |
|---|---|---|---|---|---|
| 条数 | 5,000 | 5,000 | 4,997 | 3 | 待查 |
| 金额汇总（分） | 128,450,000 | 128,450,000 | 128,442,700 | 7,300 | 随缺失单 |
| 主键集合 | 5,000 | 5,000 | 4,997 | 3 | 三条未写入 |

三条失败均为结算编号为空，属源数据问题；补映射后重放，条数与金额差异归零，报告随批次归档。

## 脚本

无脚本。清洗与脱敏可用数据处理工具完成；对账口径与销毁记录必须落文档，不能只存在临时目录。

## 完成验证

- [ ] 授权、范围、保留期限已确认。
- [ ] 原始快照有校验和，清洗基于快照。
- [ ] 清洗顺序正确，业务语义未被修改。
- [ ] 脱敏保结构、保关联，映射表单独加密存放。
- [ ] 残留扫描通过（结构化字段与自由文本都查）。
- [ ] 回放前对账四件一致。
- [ ] 回放顺序、幂等、隔离、限速都有落实。
- [ ] 回放后对账与还原完成，销毁有记录。

## 常见踩坑

- **生产数据直灌**：判据是测试库出现未脱敏的真实主键；做法是先快照、后脱敏，授权范围期限三件齐；反例是赶进度直接恢复生产备份。
- **脱敏破坏关联**：判据是跨表关联命中数骤降；做法是以主体键为算法输入，同一自然人全流程同值；反例是每张表各自随机替换账号。
- **只脱结构化字段**：判据是备注、日志、文件名仍能搜到原值；做法是把自由文本与导出文件纳入扫描清单；反例是跑完字段规则就宣布脱敏完成。
- **清洗改业务值**：判据是清洗前后金额或状态分布有无解释偏移；做法是只做格式转换，语义改动单独审批；反例是把异常单金额改成均值让报表好看。
- **对账只对条数**：判据是条数一致但金额或主键有差；做法是条数、主键集合、金额汇总、字段分布四项都过；反例是 count 相等就签字回放。
- **回放不限速**：判据是错误率随速率上升、延迟飙升；做法是令牌桶起步低位，按错误率阶梯上调；反例是一上来全量并发把环境打挂。
- **样本不销毁**：判据是保留期到期后仍在个人目录或临时盘找到样本；做法是销毁清单加到期提醒、销毁后抽验；反例是只删库里的行，导出文件留在桌面。
- **重复回放重复入账**：判据是同一批次重放后条数翻倍；做法是批次号加报文序号做幂等键，或先清后放；反例是失败后直接从头再跑一遍。
- **时间窗边界错**：判据是回放数据比预期多一天或少一天；做法是统一定义半开区间并写进口径文档；反例是一处用 between、一处用小于等于。
- **带差异回放**：判据是对账差异未定位就开跑；做法是差异落到具体步骤与条数，修完重对再放；反例是「差几条不影响」直接开跑。
