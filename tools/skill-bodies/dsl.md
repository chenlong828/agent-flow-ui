## 适用场景

低代码工程的能力大量落在 DSL 资产里：页面模型、服务编排、扩展点、路由、参数映射、权限点。改动前要先确认「这个节点、这个扩展点、这个配置项到底在不在」，不能凭命名猜。

本技能只做 DSL 资产检索与命中判读，不修改 DSL，不读原生代码。修改配置走低代码开发；原生代码检索走代码检索。

触发词：DSL、扩展点、节点、配置项、页面模型、服务编排、资产检索。

不适用：原生代码仓检索；需要改 DSL；需要业务入口定位。

## 执行步骤

### 第一步：限定检索范围

先定三个边界：哪个工程、哪个模块、哪类资产。低代码工程通常按业务模块分目录，DSL 按类型存放在不同子目录（页面、服务、扩展、路由、权限）。

范围不定就全仓搜，命中成百上千条，无法收敛。范围过窄又会漏掉跨模块引用，所以第一轮按模块，第二轮再按引用扩散。

### 第二步：把业务词拆成检索词

用户给的是业务说法，DSL 里存的是节点名、英文标识、拼音或缩写。拆词顺序：

1. 原词直搜，确认有没有同名节点。
2. 同义词与别名：中英文、全称缩写、业务别名。
3. 结构词：动词加名词，如「导出扩展点」「查询服务」「菜单路由」。
4. 标识词：驼峰、下划线、点分三种写法各试一次。

只搜一个词就下「不存在」的结论，是 DSL 检索最常见的错。

### 第三步：选检索命令与参数

DSL 是文本，用 `rg`（ripgrep）即可，命令按先量级、再文件、后上下文排列：

| 目的 | 命令形态 | 参数作用 |
|---|---|---|
| 看规模 | `rg -c '标识' <模块>` | 只出计数，过百收窄 |
| 定位文件 | `rg -l '标识' <模块>` | 只列文件名、不刷屏 |
| 读上下文 | `rg -n -C 4 '标识' <模块>` | 带行号，前后各四行 |
| 多写法 | `rg -n -e 'aExt' -e 'a_ext'` | 可重复给模式 |
| 限类型 | `rg -n -g '*.json' -g '!dist/**' '标识'` | 白名单，`!` 取反 |

点分标识要加 `-F`，否则点号当通配符；`-i` 与 `--max-count` 会把结论带偏，前者拉进无关变量，后者截掉靠后的定义处。

### 第四步：按资产类型检索

| 资产 | 特征 | 检索要点 |
|---|---|---|
| 页面模型 | 页面结构、组件树、绑定 | 按页面名与路由搜，确认页面归属模块 |
| 服务编排 | 服务定义、入参出参、调用链 | 按服务名搜，确认是否被页面引用 |
| 扩展点 | 扩展接口与实现 | 先搜扩展点声明，再搜实现注册 |
| 路由与菜单 | 路径、菜单项、权限 | 按路由片段搜，确认是否已占用 |
| 参数映射 | 字段映射、字典映射 | 按源字段与目标字段搜，确认映射方向 |

扩展点要区分「声明存在」与「实现存在」：只有声明没有实现，配了也不生效；只有实现没有声明，注册不上。两者都命中才算可用。

### 第五步：判命中真伪

命中不等于可用，逐条核对：

- 同名不同义：名字一样但属于另一个模块或另一条业务线，不能直接复用。
- 注释掉的节点：检索能命中，运行时不存在。
- 模板占位：模板里有节点，实例工程没生成，属于「模板有、实例无」。
- 版本差异：旧版本有、当前版本已删除，按当前分支为准。

判读结论分四类：确认存在、存在但不可用、不存在、无法判定。无法判定时给出还需要什么证据，不硬判。

### 第六步：查引用与影响

改 DSL 前必须知道谁在引用：

- 正向引用：这个节点被哪些页面、服务、路由引用。
- 反向依赖：这个节点依赖哪些字典、参数、服务。
- 同名节点：多处定义时，确认哪一处生效。

引用关系不清就改，常见后果是「改了一个页面，另一个页面白屏」。引用查完，把影响面写进结论。

### 第七步：扩散跨模块引用并填影响清单

扩散从命中标识出发，控制在一跳：

- 出发：标识原文与变体在工程根检索，命中分定义处与引用处。
- 一跳：读引用处所属模块与类型，再读节点自身引用型字段，列出依赖的字典、参数、服务。
- 收口：公共字典、组件、路由才做第二跳；跨业务线同名不扩散，同模块同名先合并。

变更前把影响清单六项填齐，缺项标待确认：

| 项 | 内容 | 取处 |
|---|---|---|
| 变更对象 | 资产类型与节点标识 | 定义路径与行号 |
| 直接引用方 | 引用它的页面、服务、路由 | 引用处检索结果 |
| 依赖项 | 它引用的字典、参数、服务 | 节点内引用型字段 |
| 生效条件 | 注册、挂载、开关、版本分支 | impls、菜单表 |
| 同类先例 | 其他模块对同类节点的改法 | 跨模块检索 |
| 回退点 | 改动前原值与分支 | 版本记录或快照 |

### 第八步：按判定矩阵定结论

命中只说明文本出现过，判成可用要三问都答完：

| 存在 | 生效 | 被引用 | 判定 | 后续动作 |
|---|---|---|---|---|
| 是 | 是 | 是 | 可用 | 复用，评估引用面 |
| 是 | 是 | 否 | 就绪未接入 | 可启用，先查漏挂菜单 |
| 是 | 否 | 是 | 已引用未生效 | 引用方跑空实现，先补注册 |
| 是 | 否 | 否 | 桩节点 | 只作命名线索 |
| 否 | 不适用 | 是 | 引用悬空 | 运行时兜底或报错 |
| 否 | 不适用 | 否 | 不存在 | 五种写法搜过才可下 |
| 无法判定 | 无法判定 | 无法判定 | 待证据 | 写明缺哪份文件 |

存在指读到活动定义；生效指注册、挂载、开关、版本四类条件满足；被引用指有上游页面、服务或路由引用。

### 第九步：输出检索结论

每条结论包含：资产类型、节点标识、文件路径、命中片段、结论类别、引用方、证据等级。

证据等级：直接读到定义并确认生效为高；只读到引用未见定义为中；模板或历史版本为低。低等级只能作线索。

## 示例

**示例一：查导出扩展点**

用户说「加个导出」。先按「导出」直搜，命中三个同名扩展点；分别看所属模块，两个属于其他业务线，一个属于当前模块；再看实现注册，当前模块的扩展点只有声明没有实现。结论：扩展点存在但未实现，需要补实现，不能直接配置。

**示例二：查页面路由**

用户说「委托查询页」。按页面名与路由两种写法搜，命中路由 `/query/entrust` 与页面模型；再查菜单表确认路由已注册、权限点已配。结论：页面存在、路由已占用，新增页面要换路径。

**示例三：同名节点**

改一个字段映射，检索到两处同名映射，一处是模板、一处是实例。按当前分支确认实例生效，模板不生效。结论：只改实例，模板保留；影响面只涉及当前页面。

**示例四：一次完整检索的结论表**

用户说「客户资料导出缺风险等级，是不是扩展点没实现」。拆出 `custExport`、`exportExt`、`导出扩展` 三组词，按第三步、第七步、第八步依次检索：

| 资产 | 节点 | 路径 | 证据等级 | 结论 |
|---|---|---|---|---|
| 页面模型 | custProfile | `cust/dsl/page/cust-profile.json:8` | 高 | 存在，已挂菜单 |
| 路由 | /cust/profile | `cust/dsl/route/route.json:44` | 高 | 已占用 |
| 扩展点声明 | custExport | `cust/dsl/extension/export.json:12` | 高 | 存在 |
| 扩展点实现 | custExportHandler | `cust/dsl/extension/impl-registry.json:31` | 中 | 已注册，实现体未读到 |
| 参数映射 | riskLevel | `cust/dsl/mapping/export-field.json:19` | 高 | 存在，target 指向旧列名 |
| 字典 | risk_level | 三种写法均未检出 | 低 | 不存在，映射取不到值 |

结论：扩展点存在且已注册，缺的是映射目标列名与字典，改动落在映射与字典。

## 常见踩坑

- **一个词搜不到就不存在**：判据是别名与缩写没试；做法是各补一轮再定论；反例是搜「委托查询」判无，实际叫 `entrustQuery`。
- **把模板当实例**：判据是路径带 template 或只在脚手架目录；做法是确认属实例工程；反例是模板有导出节点、实例没生成，配了不生效。
- **只看声明不看实现**：判据是读到 pointId 却没读到 impls；做法是两处都读到才算可用；反例是声明齐全但 impls 为空，配了不生效。
- **同名直接复用**：判据是多处同名未比对所属模块；做法是按模块分组只留当前模块；反例是两模块都叫 `queryService`，复用后串业务。
- **不看引用就改**：判据是只读定义、无引用方清单；做法是改动前按模块列出引用方；反例是改了公共页面映射，另一页面白屏。
- **注释节点当可用**：判据是命中片段在注释块或关闭分支里；做法是读上下文确认在活动块内；反例是注释掉的 `exportExt` 被当成已配置。
- **低等级证据进方案**：判据是只看到引用处没看到定义处；做法是低等级只进待确认；反例是凭一条路由引用写「已实现」，被推翻。
- **点分标识当普通串搜**：判据是检索词含点号却没加 `-F`；做法是含点、括号、竖线的标识统一加 `-F`；反例是搜 `risk.level` 命中 `riskXlevel`。
- **构建产物当真命中**：判据是命中路径在 dist、node_modules 下；做法是默认排除产物目录；反例是 dist 里有节点而源码已删，改动落空。
- **影响面扩散过头**：判据是清单里混进跨业务线同名节点；做法是扩散前按模块归类；反例是把公共字典同名引用全算进影响面。
