## 适用场景

你拿到业务逻辑、需求、已有 SQL 或版本脚本，要把它变成能在目标库正确执行、能被审核、能重复运行的 SQL。本技能覆盖连接验证、表结构定位、查询编写、落库与参数脚本、方言适配、审核与 EXPLAIN 判读。

| 场景 | 输入 | 产出 |
|---|---|---|
| 连接与查询验证 | 要连库看数、看计划、看元数据 | 结果集、EXPLAIN |
| 表结构定位 | 只知业务概念，不知表与字段 | 表名、字段清单 |
| 编写查询或落库语句 | 给业务规则要写 SQL | 带列依据的 SQL |
| 升级与参数脚本 | 要按方言交付版本脚本 | 合规脚本 |
| 已有 SQL 审核 | 已有脚本要过门禁 | 结论与建议 |

本技能只负责“怎么写对、怎么验对”。字段清单运行时取；不替代代码审核流水线；不执行生产写入与 DDL，DDL 走脚本仓。无库可连时只能静态审核，不能声称做过 EXPLAIN 实测。

触发词：写 SQL、SQL 脚本、表结构、字段清单、方言差异、EXPLAIN、落库脚本、参数脚本、脚本审核、SQL 门禁。

不适用：数据库备份恢复与容量运维；只改应用配置且不产生 SQL；要求直接改生产数据。

## 执行步骤

### 第一步：判场景与授权等级

先判动作会不会改变数据或结构，再决定能不能动手。等级判错，SQL 写得再对也无效。

| 等级 | 动作 | 前置与执行 |
|---|---|---|
| L0 | 只读查询、EXPLAIN、元数据 | 无前置，只读执行器限行数 |
| L1 | 测试库写入 | 依据链加测试环境白名单 |
| L2 | DDL | 依据链加人工确认，交脚本仓 |
| L3 | 生产写入或 DDL | 人工门禁，不在执行面内 |

判据是语句会不会让数据或结构变化。做法是先定级；写操作先用同条件 SELECT 确认命中行数与范围，再提交。反例是先执行 UPDATE 再看影响了几行，或连生产库试跑“应该没问题”的语句。测试库白名单不明确时按不允许处理，先问清楚，不靠猜测放行。

有五条红线：不得凭空写列名与类型，不得把单方言当四方言通用，写操作必须先验证影响面，脚本必须写 commit 与结束符，凭据不得入仓。

### 第二步：定位表结构与核对列

业务词先定位候选表，再确认读写面，最后取结构定义。写入面是业务动作最终落到的表，读取面是页面或接口取数的表，方向判错，写出的数据永远不会被消费。

判据是你无法从业务词直接说出表名，或表名来自记忆、旧脚本、聊天记录。做法是先用业务词与实体检索候选表，确认承担写入还是读取，再用 `.table` 取字段、类型、长度、主键与索引，用 `stdfield` 取中文名、标准长度与值域。反例是看到“费用”就猜一张 `t_fee`，或拿三年前的脚本列名直接写 INSERT。

表结构定义的权威顺序是结构文件优先，库内 DESC 只作参考，因为库可能是旧结构或缺注释。判据是列定义在结构文件与库内不一致。做法是逐列回到 `.table` 与 `stdfield`，DESC 只用来确认当前库是否已升级。反例是 DESC 看到一列就当标准定义，忽略长度、非空与默认值差异。

每条 SQL 过五条核对：列清单等于 `.table` 实际字段，含非空与默认值；WHERE 字段有索引，并用 EXPLAIN 验证；主键与唯一键冲突已预判，replace、merge 语义按方言处理；新增字段已在库表映射、视图加载、字段映射配置里同步；字符集与精度按 `stdfield` 标准长度，不按当前库的偶然值。

### 第三步：核对目标方言

判据是脚本最终投递到哪个方言目录。做法是逐维度过差异表，不能只改分页就交付。反例是把 MySQL 的 LIMIT 直接放进 Oracle 脚本，或把 Oracle 的 `||` 拼接带进 MySQL。

| 维度 | MySQL 与 OceanBase | Oracle | Gauss 兼容模式 |
|---|---|---|---|
| 日期 | NOW()、CURDATE() | SYSDATE | SYSDATE，同 Oracle |
| 分页 | LIMIT n,m | ROWNUM 或 OFFSET FETCH | 按版本支持 LIMIT 或 ROWNUM |
| 拼接 | CONCAT(...) | `||` | `||` |
| 空串 | 空串就是空串 | 空串等于 NULL | 同 Oracle |
| 自增 | AUTO_INCREMENT | SEQUENCE 或 IDENTITY | SEQUENCE 或 IDENTITY |
| DDL 事务 | 隐式提交 | 可回滚，仍需 commit | 同 Oracle |

Oracle 空串要单独记：判据是条件里出现 `= ''`。做法是改写成 `IS NULL`，或在写入时用非空默认值避免空串。反例是照搬 MySQL 的 `WHERE remark = ''`，在 Oracle 里永远匹配不到行，还容易误判成没有数据。

GoldenDB 按 MySQL 语法写，连接走 MySQL 协议；大结果集与大表操作不能一个事务做完，脚本侧避免全量 DML，分批交给平台层。Gauss 只作方言参考，不作默认交付目标。

### 第四步：编写查询或脚本

写查询只生成 SELECT，列名显式，不用星号；WHERE 落在有索引字段；默认 LIMIT 100；需求模糊时补条件并说明假设。反例是全表拖库，或把“最近的数据”理解成不加条件。

写脚本先判类型：参数脚本只改配置表的少量值，升级与开通脚本是 DDL 与 DML 混合的多语句块，两类骨架不能互套。命名是 `{参数编号}_{表名}-{描述}.sql`，MySQL 版不带方言后缀，其余目录带 `({方言})` 后缀。反例是 `update.sql`、`test1.sql` 这种无法判断用途与顺序的名字。

脚本头写明变更目的、影响表与字段、执行前提、幂等与重跑行为、回滚方式、变更单号与日期，让人只读脚本就能判断能不能执行。反例是只有一行 UPDATE，没有任何说明。

参数脚本按方言收口：MySQL 与 OceanBase 是注释、UPDATE、commit；Oracle 用同名 spool 包裹并以 spool off 结束；Gauss 用 begin 包住语句，commit 后写 END 与独立斜杠。Oracle 缺斜杠报 PLS-00103，是硬错误。升级脚本块内多语句，每段前写用途注释，最后 commit。

幂等写进 WHERE：脚本可能重跑时加状态守卫，只把未处理行改成已处理。反例是只判存在就覆写，重跑会回退人工修改。

跨库交付成对：四份脚本字段与取值逐格对齐。反例是只改 MySQL，其余仍是旧值，新装与升级分叉。

### 第五步：连接执行与结果判读

连接配置放在不入库的独立文件里，凭据加密或走系统凭据，仓里只留结构模板。判据是配置会不会被提交。做法是新增环境照抄模板，密码为空时不连接并提示补配置；执行前先看驱动状态，再测连接，最后跑语句。反例是把账号密码写进脚本参数或提交到仓库。

执行器只允许 SELECT、EXPLAIN、SHOW、DESC，写与 DDL 不在执行面。每次查询必须设行数上限，默认一百行，需要更多时显式调大并说明理由。判据是结果集可能很大。反例是不设上限查大表，把内存与网络拖垮。

结果分三层判读：连接层失败是环境或通道问题，不能当成业务没数据；SQL 层语法或权限错误如实报并修语句；业务层 0 行可能真无数据，也可能条件不匹配，要换条件交叉验证，例如放宽时间、去掉状态条件、先查全表计数。反例是查一次没结果就回复系统没有记录。

### 第六步：审核、EXPLAIN 与结论

规则检查覆盖三十五个规则、十四个分类，先看分类定位问题域，再看具体规则编号：

| 分类与条数 | 关注点 |
|---|---|
| 危险操作（10） | 无 WHERE、DROP、TRUNCATE、ALTER、分区清除、导入导出、锁表 |
| 语法校验（3）、模板检查（1） | 空括号、重复分号、重复 FROM、模板指令配平 |
| 编码检查（1） | 全角标点混入代码区 |
| Oracle 卡点（1）、MySQL 卡点（1） | 匿名块缺斜杠、存储过程缺 DELIMITER |
| 幂等性（2）、存量意图（2） | 恒真守卫、强制覆写、语义变更 |
| 跨库适配（2）、数据一致性（1） | 取值差异、成对文件缺失、初始数据不一致 |
| 跨文件规则（2）、风格规则（3） | 重复更新、缺变体、SELECT *、LIKE 通配、OR |
| 性能分析（4）、执行检查（2） | 全表扫、行数过大、未用索引、代价高、语法失败 |

分级两层不能混用。意见级别看 `severity`，红色线给 ERROR、提醒给 WARNING，只影响审核意见，不阻断交付。交付门禁看 `delivery_gate`，命中且本次引入才阻断；门禁十六条，覆盖危险操作九条、幂等一条、跨库适配两条、一致性一条、意图一条、Oracle 一条、MySQL 一条。

判据是命中是不是本次改动引入的。做法是本次引入的门禁命中判 BLOCK，存量命中降级 SUGGEST，不阻断。反例是把存量算到本次头上，或放过本次新引入的无 WHERE UPDATE。旧字段 `block_rules_high` 是兼容别名，禁止新增使用。

WARNING 与未进门禁集的规则不阻断，留给语义判断：注释与语句是否一致、业务条件是否缺失、跨表取值是否一致。判据是机器只判语法与模式，判不了意图。做法是对照变更单逐条确认。反例是规则全绿就通过，忽略注释与语句不符。

EXPLAIN 看四个信号：

| 信号 | 判读 | 处理 |
|---|---|---|
| type 为 ALL | 全表扫描，大表是缺陷 | 补索引或收紧条件，小配置表可接受 |
| key 为 NULL | 没命中索引 | 回 `.table` 核对索引字段 |
| rows 估算值 | 与 LIMIT 和业务量级对照 | 过大时改写条件或分页 |
| Extra 含 filesort 或 temporary | 排序或临时表成本 | 大数据量补排序索引或拆查询 |

结论只有通过与不通过：没有高风险项为通过，存在高风险或阻断项为不通过。报告写风险等级、问题类型、修改建议，并给出高、中、低、信息计数。误报走留痕撤回，不能手改结果 JSON；规则分级只改配置再重新生成清单。

## 示例

**示例一：带索引与限行的查询**

需求是查某日之后仍未结算的委托，按创建时间倒序取前一百条：

```sql
SELECT order_no, status, create_time
  FROM t_order
 WHERE status = 'UNSETTLED'
   AND create_time >= '2026-10-18 00:00:00'
 ORDER BY create_time DESC
 LIMIT 100;
```

列名来自结构文件。EXPLAIN 命中 `idx_status_create`，key 非空，rows 约一百二十，结论通过。同一查询放到无索引的大表上，type 为 ALL、key 为 NULL、Extra 含 filesort，则判性能缺陷，先补索引或收紧时间范围。

**示例二：参数落库脚本的三种骨架**

MySQL 与 OceanBase 版，脚本头写清目的、影响列与可重跑，WHERE 带状态守卫：

```sql
-- 9001_t_sys_param-enable_fee_freeze
-- 目的：开启费用冻结校验；影响：t_sys_param.param_value；可重跑
UPDATE t_sys_param
   SET param_value = '1'
 WHERE param_no = '9001'
   AND param_value <> '1';
COMMIT;
```

Oracle 版用 spool 包裹，名与脚本同名，结尾关闭：

```sql
SPOOL 9001_t_sys_param-enable_fee_freeze(oracle)
UPDATE t_sys_param SET param_value = '1'
 WHERE param_no = '9001' AND param_value <> '1';
COMMIT;
SPOOL OFF
```

Gauss 版把同样的 UPDATE 包进 begin 与 END，commit 后单独一行斜杠。三份脚本字段与取值完全一致，命名只差方言后缀。

**示例三：审核不通过**

送审 SQL 是 `UPDATE t_order SET status = 'SETTLED';`。规则检查命中无 WHERE 的 UPDATE，ERROR 且命中门禁、本次引入，判 BLOCK。另一份 Oracle 脚本匿名块有 END 但缺独立斜杠，命中 Oracle 卡点，同样 BLOCK。结论不通过，阻断两条。修改建议是补 `WHERE order_no = ? AND status = 'UNSETTLED'` 并在块末补斜杠。

## 脚本

本技能不新增脚本，执行器是仓内既有工具。环境键与仓路径按实际替换，凭据不写在命令行：

```bash
python tools/sql_agent/db_connector.py --db <环境键> --test
python tools/sql_agent/sql_executor.py --db <环境键> --sql "SELECT ..." --limit 100
python tools/sql_agent/metadata_reader.py --table <表名>
python tools/sql_agent/sql_auditor.py --sql "<SQL>" --level default
python tools/sql_agent/sql_rule_checker.py --repo <仓> --base <基线> --tip <变更>
```

执行前先跑帮助确认参数，再测连接，最后执行语句。审核级别 basic 只查危险操作，default 增加语法与 EXPLAIN，strict 增加风格提示。diff 模式门禁命中且本次引入时退出码为 2，编排按退出码判失败。结果按契约收口：

```json
{"scene":"","dialect":"","objects":[{"table":"","source":".table|desc","columns":[]}],"sql":"","explain":{"type":"","key":"","rows":0,"extra":""},"rules":[{"rule_id":"","severity":"","delivery_gate":true,"introduced":true}],"conclusion":"pass|block","notes":[]}
```

`objects` 记录表名与列依据，`explain` 没有实测时留空并在 `notes` 说明，`rules` 只列命中项，`conclusion` 与门禁一致。

## 完成验证

- [ ] 场景已判定，授权等级与动作匹配，没有越级执行。
- [ ] 表名来自定位结果，列清单对过 `.table`，长度与值域对过 `stdfield`。
- [ ] WHERE 字段有索引依据，EXPLAIN 已看 type、key、rows、Extra。
- [ ] 写法与目标方言一致，分页、日期、拼接、空串、自增、DDL 事务逐项核过。
- [ ] 查询只含 SELECT，列名显式，带 LIMIT，假设已说明。
- [ ] 脚本命名与方言后缀合规，脚本头齐全，有 commit；Oracle 有 spool 与 spool off，Gauss 有 END 与独立斜杠。
- [ ] 写操作有 WHERE 与状态守卫，跨库脚本成对且逐格一致。
- [ ] 审核结论与门禁一致，存量豁免已区分，报告含风险等级、问题类型、修改建议与计数。
- [ ] 没有客户名、项目号、内网地址、库实例名与明文凭据进入脚本或结论。

## 常见踩坑

- **凭记忆写列名**。判据是列名没在结构文件出现。做法是回 `.table` 逐字段核对。反例是照旧脚本抄了已改名的列，执行报未知列。
- **单方言写法直接通用**。判据是脚本要进多个方言目录。做法是逐维度过差异表。反例是把 LIMIT 带进 Oracle，或把空串判断带进 Oracle 后误判为无数据。
- **无 WHERE 的 UPDATE 或 DELETE**。判据是语句会改多行。做法是先同条件 SELECT 确认行数，再加主键或状态守卫。反例是先执行再看影响行数，回滚不及时就污染数据。
- **脚本缺收口**。判据是脚本没有 commit，或 Oracle、Gauss 块没有结束符。做法是按方言骨架逐行核对。反例是 Oracle 匿名块只写 END 不写斜杠，升级直接报 PLS-00103。
- **把意见级别当交付门禁**。判据是命中是否在门禁集内、是否本次引入。做法是分别看 `severity` 与 `delivery_gate`。反例是看到 ERROR 就阻断，或看到 WARNING 就放过本次新引入的风险。
- **业务层 0 行就当无数据**。判据是只跑了一次带条件的查询。做法是换条件交叉验证，先确认连接与权限正常。反例是条件写错却回复系统没有记录，把排查方向带偏。
