## 适用场景

你要在 CRES 框架内写代码或出技术方案。CRES 工程有一套固定的运行时、基类、数据访问层与扩展点；绕过它们直接写，代码能跑，但升级、权限、事务、审计都会出问题。

本技能约束「怎么在框架里写」：识别工程、找基类、走数据层、用扩展点、按规范自检。不负责业务方案设计，也不负责页面视觉。

触发词：CRES、基类、数据层、扩展点、框架规范、组件运行时。

不适用：非 CRES 工程；纯原生页面；只改配置不改代码。

## 执行步骤

### 第一步：确认是不是 CRES 工程

三条判据同时看：工程依赖里有 CRES 运行时；目录结构符合框架约定（页面、组件、服务、模型分层）；入口由框架接管而不是自己 new。

只满足一条时不要按 CRES 规范套，先确认技术栈。判错栈会让方案里的类名、目录、生命周期全部对不上。

### 第二步：先找基类与扩展点

写之前先查三样：

| 要找的 | 在哪找 | 找到后怎么用 |
|---|---|---|
| 页面/组件基类 | 框架组件库与工程内基类目录 | 继承基类，不直接继承框架底层类 |
| 数据访问层 | 工程数据层目录 | 通过数据层访问，不在页面里拼 SQL 或直连 |
| 扩展点 | 框架扩展点清单与工程扩展实现 | 在扩展点里加逻辑，不改框架源码 |

基类提供生命周期、权限、异常、日志等能力。绕开基类自己实现一遍，等于放弃这些能力，后续框架升级也会冲突。

扩展点找不到时，先查框架版本的扩展点清单，再查同类工程的实现；仍找不到就问架构，不往框架源码里加代码。

### 第三步：按分层写

| 层 | 职责 | 禁止 |
|---|---|---|
| 页面/组件 | 展示、交互、校验提示 | 直连数据库、写业务事务 |
| 服务 | 业务编排、事务边界 | 拼接页面文案、依赖会话 |
| 数据层 | 查询与持久化 | 写业务判断、拼装展示结构 |
| 模型 | 数据结构与校验 | 依赖页面上下文 |

跨层调用只允许相邻层向下，不允许页面直接调数据层，也不允许数据层回调页面。事务边界放在服务层，页面不手动提交事务。

### 第四步：守命名与配置

命名：类名体现业务与层（如「委托查询服务」），方法名用动词开头，常量全大写，配置键用小写点分。同一个概念在页面、服务、模型里用同一个词，不换同义词。

配置：环境地址、开关、超时、分页大小放配置，不写死在代码里。配置项要有默认值与说明；敏感配置走凭据，不进代码库。

### 第五步：处理异常、日志与权限

异常：业务异常与系统异常分开；业务异常给用户可读提示，系统异常记日志并给通用提示，不把堆栈抛给页面。

日志：关键操作记操作人、对象、结果；日志里不打印密码、令牌、完整证件号。排查用的详细日志用调试级别，默认关闭。

权限：页面按钮、接口、数据行三级权限分别校验；前端隐藏不等于后端放行，后端必须再校验一次。

三个横切主题与上面五步同时适用，末尾进第六步自检。

### 框架生命周期的阶段与钩子

五阶段顺序固定：构造注入、初始化、数据加载、渲染绑定、销毁，钩子能力按阶段受限：初始化只装默认值与配置，不碰未挂载节点；数据加载经服务层取数填模型，不改展示节点；渲染绑定只绑事件与格式化；销毁解绑事件、取消订阅与定时器，不引用已释放父级。父级先初始化、子级先销毁；异步钩子须返回可等待结果，否则框架在数据未就绪时渲染，出现空列表。

### 错误模型与返回结构

错误分三层：校验（用户可改）、业务（规则拒绝）、系统（代码或依赖故障），共用一套信封：code 按号段分配，校验 4、业务 5、系统 6，段内按模块切；message 只写用户能照做的话；detail 只进日志与调试面板；traceId 由框架生成随提示带出。抛出用框架异常类型再转换，页面不拼 code；catch 只在能处理或转换处接，其余冒泡给框架；异常不得吞掉后返回空数据。

### 事务与并发控制

边界在服务层，画多大与并发怎么防是两件事。一个服务方法一个事务，方法内不再调带事务的服务方法，公共逻辑下沉数据层；隔离默认用框架配置，要稳定快照才显式提高并评估锁等待；并发改同一行用版本号列，影响行数为零即判冲突，返回业务错误让用户刷新，不静默覆盖；提交、支付、撤单带幂等键，重复请求返回首次结果；死锁与锁超时有限重试并退避，业务错误不重试；事务内不发远程调用、不发消息、不循环大批量。

### 第六步：自检与规范检查

提交前跑框架规范检查：基类继承、分层调用、命名、配置外置、异常处理、日志脱敏。检查不通过不提交；规则误报要登记豁免，不直接关规则。

## 示例

**示例一：页面新增字段**

需求：委托查询页加「对手方代码」列。做法：页面继承查询基类，列配置走基类提供的列定义；数据从服务层返回的模型取，不在页面里二次查询；字段为空时显示占位符，不显示 undefined。自检：未直连数据层、未改框架源码、列配置在基类扩展点内。

**示例二：服务加事务**

需求：批量撤单要么全成功要么全失败。做法：事务边界放服务层，循环内调用数据层单条操作，异常时整体回滚；页面只处理结果提示，不手写提交或回滚。自检：事务注解在服务方法上，数据层无事务控制。

**示例三：扩展点加校验**

需求：保存前加业务校验。做法：在保存扩展点实现校验，返回框架约定的错误结构；不改基类保存方法。自检：扩展点已注册、错误结构符合契约、页面能展示提示。

**示例四：服务的完整骨架**

需求：撤单服务接入框架，含基类继承、扩展点注册、事务与异常转换。

```java
public class EntrustCancelService extends BaseBizService {  // 继承服务基类
    @Inject
    private EntrustRepository entrustRepository;            // 只依赖数据层

    @Override
    protected void registerExtensions(ExtensionRegistry registry) {
        registry.register("entrust.beforeCancel", new CancelValidator());
        registry.register("entrust.afterCancel", new CancelAuditWriter());
    }

    @Transactional(rollbackFor = Exception.class)
    public CancelResult cancel(CancelCommand command) {
        try {
            Entrust e = entrustRepository.lockById(command.getEntrustId());
            if (e == null || !e.canCancel()) {
                throw new BizException(ErrorCode.BIZ_STATE_CONFLICT, "当前状态不允许撤单");
            }
            entrustRepository.updateStatus(e.getId(), Status.CANCELED, command.getOperator());
            return CancelResult.ok(e.getId());
        } catch (BizException ex) {
            throw ex;                     // 业务异常原样上抛
        } catch (Exception ex) {
            log.error("撤单失败 entrustId={}", command.getEntrustId(), ex);
            throw new SysException(ErrorCode.SYS_INTERNAL, "系统繁忙，请稍后重试");
        }
    }
}
```

要点：继承服务基类而非底层类，扩展点只在注册方法里挂，业务异常原样上抛、系统异常换统一错误码并记堆栈。自检：类在服务层、依赖只有数据层、错误码取号段常量。

## 常见踩坑

- **绕过基类**：自己实现生命周期与权限，短期能跑，升级即冲突。判据：继承链上没有基类。做法：继承最近基类，钩子填差异。反例：自管销毁顺序，父级释放后仍回调子级，报空引用。
- **页面直连数据层**：事务、权限、审计全部失效。判据：页面出现数据层类名或 SQL。做法：经服务层取数，页面只消费模型。反例：查库绕过行级权限，越权数据照常显示。
- **改框架源码**：升级被覆盖，问题无法复现。判据：改动落在框架目录或依赖包。做法：走扩展点，不够提给维护方。反例：改基类保存方法，升级后线上线下不一致。
- **业务逻辑放数据层**：复用困难，测试难写。判据：数据层方法里有状态判断或分支。做法：数据层只做查询与持久化。反例：状态机塞进仓储，别处复用被隐式改状态。
- **配置写死**：换环境要改代码，容易把生产地址带进测试。判据：代码里有环境地址、超时数字、开关值。做法：键进配置清单并带默认值。反例：测试环境连生产库，联调写脏数据。
- **前端隐藏当权限**：接口没校验，越权只需直接调用。判据：后端接口无权限校验或数据范围过滤。做法：按钮、接口、数据行后端都校验。反例：抓包重放即可撤走他人委托。
- **日志打敏感信息**：排查方便，泄露风险也来了。判据：日志里有密码、令牌、完整证件号。做法：脱敏或只记摘要，详细日志用调试级别。反例：调试日志令牌被日志平台长期留存。
- **异步钩子不等待**：界面先渲染后填数，出现空态闪动。判据：钩子发异步请求却不返回可等待结果。做法：钩子返回可等待对象，就绪后再渲染。反例：列表先空态，数据回来才填。
- **事务里做远程调用**：判据：事务方法内调外部接口或发消息。做法：调用移出事务，先落库再异步补偿。反例：接口超时，事务长期持锁，连接池被打满。
- **吞异常返回空**：判据：catch 后返回空集合或 null 且无日志。做法：业务异常转错误码上抛，系统异常记日志换通用提示。反例：查询失败返回空列表，故障拖三天才发现。
