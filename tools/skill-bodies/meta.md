## 适用场景

设计或开发前要先确认事实：字段在不在、参数存在哪张表、字典子项叫什么、菜单编号有没有被占用、功能号是否已注册。这些都不能猜，必须查到权威载体，给出路径与行号。

本技能负责元数据取证：表与字段、字典、配置、菜单、权限、功能号五类载体的定位与判读，产出可写进方案的事实清单。不负责改表、改配置、发版。

触发词：元数据、表结构、字段是否存在、字典、参数、sysconfig、菜单编号、功能号、权限点。

不适用：需要改数据（走造数）；需要读业务代码逻辑（走代码现状检查）；只需要业务入口（走业务功能树）。

## 执行步骤

### 第一步：把问题归到五类载体

| 类别 | 权威载体 | 典型问题 |
|---|---|---|
| 表与字段 | 表设计文件 + 当前分支 DDL | 字段是否已存在、类型与可空性 |
| 表落地 | 建表与初始化 SQL | 方言覆盖、索引、对象注册、初始化数据 |
| 字典 | 字典条目表 + 字典子项表 | 枚举值、子项名称与顺序 |
| 配置 | 系统参数表与参数表 | 开关叫什么、默认值、归属 |
| 菜单与权限 | 菜单表、功能表、菜单功能关系、权限映射 | 菜单编号、权限点、功能号落点 |

归类错了会查错仓库：字典与参数的元数据往往不在业务仓，而在公共管理仓。先确认载体属于哪个仓，再查。

### 第二步：确认权威与优先级

同一事实有多个来源时，按优先级取：

1. 当前分支的 DDL 与初始化脚本（含注释）——最新事实。
2. 表设计文件——设计意图，可能与 DDL 有偏差。
3. 历史文档与截图——只作线索，不作结论。

表设计文件与 DDL 冲突时，以 DDL 为准，并把表设计文件标为「待重新生成」。改过表设计文件后，必须按生成链路重新生成实体与访问层，不能只改 JSON。

### 第三步：查表与字段

查表：在目标仓的表设计目录按表名找文件，读出表中文名、字段清单、类型、可空性。查字段：给表名与字段名，判断「表存在且字段存在 / 表存在但字段不存在 / 表不存在」三种结果。

类型要写原名，不臆造标准类型：产品自定义的字符、名称、编号、费率、金额类型各有含义，写错会影响方言函数判定与建表脚本。

字段存在性结论必须能回指：文件路径、字段所在行、类型原文。只说「有」或「没有」不算取证。

### 第四步：查字典与配置

字典是两张表：条目表与子项表。只改条目不改子项，页面上会出现「有字典、无子项」。查字典要同时给出条目与子项，确认编码、名称、排序、启用状态。

配置是两类表：系统配置与参数表。查参数要回答：参数名、默认值、归属系统、生效方式（重启、刷新、即时）、是否分环境。参数归属不清时，先查参数表，再查初始化脚本，最后查代码引用点。

配置与字典的元数据可能在公共仓，业务仓查不到是正常现象，不要据此判「需要新建」。

### 第五步：查菜单、权限与功能号

菜单：在菜单表或菜单配置文件里按名称或编号查，确认编号是否占用、父子关系、路由、排序。

权限：确认权限点编号、归属菜单、默认角色。权限点与菜单是多对多，不能假设一一对应。

功能号：在功能号注册表或字典里查，确认是否已注册、归属服务、是否与权限映射。功能号未注册就写进方案，发布后调用必然失败。

新建表还有一条硬要求：建表脚本之后必须补对象注册。漏注册时检查清单必然失败，且现象是「表在、服务找不到」。

### 第六步：标注证据等级并产出

证据等级：

- 高：当前分支 DDL/脚本原文，带路径与行号。
- 中：表设计文件、菜单配置，带路径。
- 低：历史文档、截图、口头说明，只能作线索。

产出格式：每条事实一行，包含问题、结论、载体路径、行号、等级。低等级结论不能直接进方案，必须升级或标待确认。

### 补充一：五类载体查询路径表

| 类别 | 检索位置 | 检索键与必读列 |
|---|---|---|
| 表与字段 | 表设计目录、当前分支 DDL | 表名、字段名、类型原文、可空、默认值 |
| 表落地 | 建表与初始化 SQL | 表名、脚本序号、方言、索引、对象注册 |
| 字典 | 公共仓条目表与子项表 | 字典编码、子项编码、排序号、启用状态 |
| 配置 | 参数表、初始化脚本 | 参数键名、默认值、归属系统、生效方式 |
| 菜单与权限 | 菜单表、功能表、权限映射 | 菜单编号、权限点编号、功能号、父子关系、路由 |

干扰项：同名历史表、开发库改过未同步、业务仓同名枚举类、硬编码常量、编号复用。

### 补充二：表设计文件与 DDL 冲突的处理流程

1. 逐字段比对名称、类型原文、可空、默认值、注释、主键与索引，两份来源都定位到文件与行号，缺一份要写明。
2. 差异分四类：DDL 有而表设计无，属实现先行，表设计待重新生成；表设计有而 DDL 无，属设计先行，不能当已存在；类型或可空不一致以 DDL 为准，列出受影响的函数与映射；索引不一致以 DDL 为准并写出性能影响。
3. 修复走生成链路：改设计源文件后重新生成实体与访问层，手改生成物会被下次生成覆盖。
4. DDL 不在当前分支时等级降为中，写明分支名与合入前提。
5. 裁决未完前两套事实并列并标待确认，不用一套替掉另一套。

### 补充三：字典条目与子项的双表核对

1. 按字典编码在条目表定位，读出名称、启用状态、是否内置。
2. 用同一编码在子项表取全部行，按排序号升序读，记编码、名称、启用状态、扩展属性。
3. 结论只落三种：两表都缺，都要补；条目在而子项缺，只补子项；两者都在但取值不符需求，先查常量引用再定改造方式。
4. 停用子项不要删除，删除会让历史单据的枚举回显为空。
5. 子项编码被常量引用时只增不改，改名就同步改引用点。

缺一张表的结论降级为待确认。

### 补充四：参数生效方式判读

- 即时生效：读取点直接查库，无缓存包装，改完下一次调用即生效。
- 缓存加刷新：值在内存或缓存里，需刷新入口、事件或定时任务重载；判据是存在刷新接口、缓存键或监听器，产出写明刷新方式与触发方。
- 重启生效：启动时一次性加载，运行期改库无效；判据是初始化阶段读取且无刷新路径，或参数表标注需重启。

另答三问：默认值在哪个脚本哪行；是否分环境、归属哪个系统；同名参数是否已被占用。

## 示例

**示例一：字段是否存在**

问题：费用模板表要不要新增 `fare_name`。查表设计文件得到 18 个字段，无 `fare_name`；再查当前分支 DDL，同样没有。结论：表存在、字段不存在，需新增。附两条路径与行号，等级高。

**示例二：字典子项**

问题：新增一个「委托状态」枚举。查条目表有该字典，子项表只有 3 项，缺「已撤单」。结论：字典存在、子项需补；给出条目编码、现有子项、缺失项。若只改条目表，页面仍不显示新项。

**示例三：参数归属**

问题：新增开关放哪。先查系统配置表无此参数；再查参数表，发现同名参数归属另一系统；最后查初始化脚本确认默认值。结论：参数已存在但归属不同，不能直接复用，需新增独立参数并写默认值。

**示例四：一次取证三件事**

问题：结算页要加「费用名称」列，以及「结算方式」字典的「月结」子项与「多币种」开关。

| 问题 | 结论 | 路径 | 行号 | 等级 |
|---|---|---|---|---|
| 费用模板表有无 fare_name | 表在、字段不在，需新增 | 表设计 fare_template.json | 12-30 | 高 |
| 当前分支 DDL 是否已建 | 未建，与表设计一致 | ddl/mysql/fare_template.sql | 8-26 | 高 |
| 「结算方式」有无「月结」 | 条目在，子项缺 | 公共仓条目表、子项表 | 条目 214，子项 88-91 | 高 |
| 多币种开关能否复用 | 在但归属财务系统，不复用 | 初始化脚本 参数表 | 403 | 高 |
| 功能号 F-2103 是否注册 | 注册表无记录，需先注册 | 功能号注册表 | 无记录 | 中 |

## 常见踩坑

- **在业务仓查字典**：判据是业务仓搜不到字典表；做法是先确认归属仓再查；反例是没搜到判需新建。
- **只看表设计不看 DDL**：判据是结论没有 DDL 行号；做法是两份都定位比对；反例是照过期设计写字段已存在。
- **字典只改条目**：判据是产出只有条目行；做法是两表成对给并写明缺项；反例是页面下拉仍空。
- **类型自造**：判据是所写类型名两处都搜不到；做法是抄原文类型名带长度精度；反例是金额类型被写成数值类型。
- **新建表漏注册**：判据是有 CREATE TABLE 而无注册语句；做法是建表与注册成对提交并给行号；反例是服务启动找不到对象。
- **低等级证据进方案**：判据是结论只来自截图或口头说明；做法是升级到文件与行号；反例是拿截图字段名当已存在。
- **只给结论不给行号**：判据是产出缺路径或缺行号；做法是每条给路径、行号、原文；反例是复核无从定位。
- **否定结论当确定事实**：判据是结论为不存在、未注册且只有一个来源；做法是换第二来源复核再定档；反例是单仓搜不到判未注册。
- **缓存当立即生效**：判据是参数有缓存键或刷新入口；做法是按三档判读并写明触发方；反例是改库后页面不变当缺陷查。
- **停用改成删除**：判据是处理方式是删子项或删字典行；做法是改启用状态保留回显；反例是老单据枚举显示为空。
