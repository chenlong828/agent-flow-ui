## 适用场景

你要在真实页面上确认现状、验证功能、复现缺陷，而不是读代码推断。浏览器可用时，以页面实测为准：截图、DOM、交互三步取证，输出可复核的页面报告。

输入是检查目标（功能号、路由或完整 URL）、检查意图（现状确认 / 功能验证 / 缺陷复现）、可选的交互序列。输出是页面状态、关键元素、截图与结论。

本技能只做只读验证：不登录、不改业务数据、不代替用户操作敏感功能。需要登录时停下来提示，不尝试代登录。

触发词：浏览器验证、页面验证、截图取证、打开页面看看、复现一下、现状确认。

不适用：浏览器不可用且无法降级；只需要读代码；需要压测或兼容性矩阵。

## 执行步骤

### 第一步：前置检查与降级

先确认浏览器自动化通道可用：驱动能启动、目标环境可达、页面能打开。任一项不满足，按降级纪律处理：先向用户报告不可用的具体原因，得到确认后才降级为代码级验证；未确认不得自行降级。

降级后交付物要如实标注「未实时复核（降级为代码扫描，原因：……）」，不能把静态推断写成页面实测。

环境异常不等于功能不存在：白屏、404、子应用内容区空白，只记环境证据，不下「功能没有」的结论。环境修复后可以只补证据，不重做全量。

### 第二步：构造 URL

功能号先按菜单知识解析成路由，再拼环境基础地址。完整地址由「环境基础地址 + 路由」组成；外层直接给完整 URL 时跳过解析。

路由解析不到时，先查菜单结构与路由表，再查页面注册点；仍解析不到就停下来问，不猜一个看起来像的地址。

### 第三步：窗口与登录态

打开页面后先把窗口调到 1920×1080，再截图。窗口过小会截掉右侧列和底部按钮，证据不完整。

等待加载完成：优先等关键元素出现，其次等网络空闲，最后才用固定等待。固定等待只作兜底，不作为唯一手段。

如果跳转到登录页，记录「需要登录」并停止，把当前状态交回调用方，不尝试输入账号密码。

### 第四步：按意图采集

| 检查意图 | 采集内容 |
|---|---|
| 现状确认 | 页面截图 + 关键元素清单（筛选条件、列、按钮） |
| 功能验证 | 截图 + 交互操作 + 操作后状态 + 与预期对比 |
| 缺陷复现 | 截图 + 复现步骤 + 错误状态与提示 |
| 未指定 | 截图 + 核心区域描述 |

关键元素至少采四类：页面标题、筛选条件、表格列头、按钮文本。元素存在但不可见、可见但禁用，都要在报告里区分，不能只写「有 / 没有」。

### 第五步：截图与证据

截图要满足三条：完整（窗口最大化、关键区域不被遮挡）、可定位（文件名带时间戳与页面标识）、可追溯（报告里引用同一文件名）。

截图存放：先落到临时目录，再复制到项目证据目录，最后确认文件存在。临时目录每次启动可能变化，不要写死路径。复制失败时报告具体错误，不把「截了但没存下来」当成功。

DOM 证据与截图配套：截图证明「看到什么」，DOM 证明「结构是什么」。两者冲突时，以页面实际渲染为准，并在报告里说明差异。

### 元素采集细则

采集优先用语义定位，其次用结构定位，最后才用坐标：

| 目标 | 优先定位 | 兜底 |
|---|---|---|
| 筛选条件 | 表单标签、占位符文本 | 表单区域内输入控件顺序 |
| 表格列 | 表头单元格文本 | 表格列索引 |
| 按钮 | 按钮文本或无障碍名称 | 工具栏区域按钮顺序 |
| 提示 | 提示区域文本、角色属性 | 页面顶层浮层文本 |

采到的元素要记三态：存在且可见、存在但隐藏、不存在。隐藏元素用坐标截图看不到，但 DOM 能查到，报告里要区分。

### 批量检查汇总

多页面时先逐页出摘要，再合并：

| 序号 | 页面 | 地址 | 可访问 | 关键发现 | 证据 |
|---|---|---|---|---|---|
| 1 | 委托查询 | /query/entrust | 是 | 新增列已展示 | 截图 01 |
| 2 | 成交查询 | /query/deal | 是 | 导出按钮禁用 | 截图 02 |

汇总表只放结论，细节留在各页报告里，避免一张表塞不下。

### 错误处理对照

| 现象 | 处理 |
|---|---|
| 驱动不可用 | 快速失败，报告后确认是否降级 |
| 页面加载超时 | 停止等待，标「加载超时」，不判功能缺失 |
| 跳登录页 | 标「需要登录」，停止，不代登录 |
| 404 或子应用空白 | 只记环境证据，环境修复后补验 |
| 元素找不到 | 标「元素不存在」，其他检查继续 |
| 截图写入失败 | 报告具体错误，不算取证完成 |

有交互序列时逐条执行：导航、点击、输入、等待、滚动、截图。每步记录操作、结果、截图；失败时记录失败现象，不中断后续无关步骤。

报告结构：

```markdown
## 浏览器页面验证报告

- 验证目标：
- 验证意图：
- 验证时间（东八区）：
- 环境地址：

### 页面状态

- 页面标题：
- 是否可访问：
- 登录状态：

### 关键元素

| 区域 | 内容 | 状态 |
|---|---|---|
| 筛选条件 | | 正常 / 缺失 / 异常 |
| 数据列 | | |
| 按钮 | | |

### 截图

### 发现与问题

### 交互结果（如有）

| 步骤 | 操作 | 结果 | 截图 |
|---|---|---|---|
```

多页面批量检查时，逐页独立报告，最后给一张汇总表：序号、页面、地址、可访问、关键发现。

## 示例

**示例一：现状确认**

目标：委托查询页。打开后窗口最大化，等表格出现，截图；采集筛选条件 5 个、列 12 个、按钮 3 个；发现「导出」按钮存在但禁用。报告写「按钮存在、当前禁用」，不写「没有导出功能」。

**示例二：缺陷复现**

目标：某查询页导出乱码。按复现步骤操作，逐步截图；执行导出后记录文件编码与页面提示；把「操作序列 + 每步截图 + 错误现象」写进报告，结论只写观察到的事实，原因分析交给排查。

**示例三：环境不可达**

打开页面白屏，控制台报资源加载失败。记录「环境证据：白屏、资源 404」，结论写「环境不可判」，不写「功能未实现」；提示环境修复后补验。

## 脚本

无脚本。浏览器操作通过自动化通道执行；截图落盘与复制用环境命令完成。报告为 Markdown，截图按时间戳命名。

## 完成验证

- [ ] 通道可用性已确认；降级有用户确认与标注。
- [ ] URL 由路由解析或外层传入，来源清楚。
- [ ] 窗口已最大化，页面加载完成后再截图。
- [ ] 关键元素四类齐全，存在/可见/可用三态分清。
- [ ] 截图完整、命名可追溯、文件确认存在。
- [ ] 结论有截图或 DOM 证据支撑；环境问题未当功能结论。
- [ ] 报告含目标、意图、时间、环境、发现五段。

## 常见踩坑

- **不最大化就截图**：右侧列和底部按钮被截掉，证据不完整。
- **固定等待代替元素等待**：页面慢时截到空白，快时白等。优先等元素。
- **把环境问题当功能缺失**：白屏、404 只能证明环境不可用，不能证明功能不存在。
- **截图没存下来**：临时目录路径写死或复制失败，报告引用不到图。落盘后必须确认文件存在。
- **代用户登录**：输入账号密码既越权也不安全。需要登录就停。
- **只截整体图不采元素**：看不出筛选条件与列的细节，复核困难。
- **交互失败就中断全部**：单步失败记录后继续无关步骤，避免一次失败丢掉整轮证据。
