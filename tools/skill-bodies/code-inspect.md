## 适用场景

你要在动手改之前回答一个事实问题：这个功能现在到底怎么实现的——入口在哪个页面、调用哪个接口、数据从哪张表来、哪些字段已经存在。输出是一份可核对的现状摘要，供需求分析、方案设计、缺陷复现使用。

输入是一组检查目标（`targets`）和一个检查意图（`check_intent`）。每个目标可以是功能号、页面路由、文件路径或完整 URL，定位优先级为：功能号 > 路由 > 文件路径 > URL。检查意图决定读多深，不决定读不读。

本技能只做定位、读取、取证三件事。不判断该不该改，不产出修改方案，不写代码，不登录业务系统，不改数据。是否进入开发流程由调用方决定。

触发词：代码现状、现状检查、这个功能怎么实现的、是否已实现、代码在哪、接口返回什么字段。

不适用：需要评估改动影响面（走影响面分析）；只需要打开页面截图（走浏览器页面验证）；只需要查业务知识（走知识库检索）。

## 执行步骤

### 第一步：归一目标

把每个目标整理成统一结构：功能号、路由、文件路径、层级（Vue / Java / DB）、一句话描述。缺什么补什么，补不上的标待确认，不猜。

- 有功能号：以功能号为主键，路由和文件都由它推导。
- 只有路由：先按路由规则归到页面仓，再找路由对应的组件。
- 只有文件：跳过推导，直接读文件，但要说明它属于哪个模块。
- 只有 URL：先拆出路由，再按路由处理。

多个目标时逐个检查，最后合并成一张汇总表；不要把所有目标混在一次检索里。

### 第二步：定位仓库与路径

先确定产品，再确定仓库，最后拼出文件路径。产品到仓库、知识入口的映射查产品映射表；仓库在本地的源码根由环境决定，不写死在技能里。

页面侧按路由前缀归属：

| 路由前缀 | 归属 | 页面目录特征 |
|---|---|---|
| /sys、/operator、/home | 管理端公共仓 | views 下按模块分目录 |
| /param、/account、/datacenter、/strategy | 管理端公共仓 | views 下按模块分目录 |
| /mgr、/asset、/query、/trans | 证券业务仓 | views 下按功能分目录 |
| /mgr、/asset、/query、/crdt、/arg | 两融业务仓 | views 下按功能分目录 |
| /monitor、/strategy、/dataSearch、/tca、/kpa、/system、/basics、/backTest、/authority | 算法总线仓 | views 下按功能分目录 |

路由到文件：在页面仓的 views 下按路由末段找同名目录，目录内通常有 `index.vue`（页面结构）与 `template.js`（筛选条件、输出列、按钮配置）。

后端侧按功能号段归属：

| 功能号段 | 归属服务 | 代码目录特征 |
|---|---|---|
| f10xxx | 证券服务 | `src/main/java/` 下按功能分包 |
| f11xxx | 两融服务 | `src/main/java/` 下按功能分包 |
| f1xxx 等公共号 | 公共服务 | `src/main/java/` 下按公共模块分包 |
| 算法类功能号 | 算法服务 | `webservice/` 下按服务分目录 |

功能号到后端文件的定位顺序：先找 `*{功能号}Controller*.java`，再找对应 `*Service*.java`、`*Input*.java`、`*Output*.java`。功能号在菜单表或字典表里有权威定义，找不到时先查字典，再查源码注册点。

目标仓库未在本地检出时，登记为待确认，收尾给「环境不可判」，不臆造路径，不用相似文件名代替。

### 第三步：按意图读代码

| check_intent | 读取范围 |
|---|---|
| 未指定 / 概览 | `template.js` 的筛选与输出配置段 + `index.vue` 的结构段 |
| 了解筛选配置 | 聚焦 `template.js` 的 filterItem 定义 |
| 确认接口返回字段 | `outputConfig` + 后端 Output 类 + Service 组装逻辑 |
| 确认查询逻辑 | Controller → Service → DAO/SQL 调用链 |
| 全量代码审查 | 完整读 `template.js`、`index.vue`、Controller、Service、POJO |

约束：单个文件最多读 500 行，超出分段读并标注截断位置；先读入口与配置，再按调用链往下，不做无目的的全仓检索；每个结论都记 `文件路径:行号`，方便复核。

### 第四步：输出摘要

```markdown
## 代码现状检查报告

**检查目标：** 功能号 / 路由 / 文件
**检查意图：** 概览 / 字段 / 查询逻辑 / 全量
**检查时间：** 东八区时间

### 定位结果

| 目标 | 功能号 | 路由 | 归属模块 | 页面文件 | 后端文件 |
|---|---|---|---|---|---|

### 页面关键配置

- 筛选条件：字段与默认值
- 输出列：列名与字段
- 按钮：名称与动作
- 特殊逻辑：前端计算、联动、权限

### 后端关键逻辑

- Controller：接口路径、入参、返回
- Service：查询条件、数据组装、事务边界
- 入参/出参：字段与类型

### 关键发现

- 已存在但未展示的字段
- 接口有但页面未调用的能力
- 空值、越权、性能风险
- 未检出项与检索范围
```

摘要只写事实与风险，不写「建议这么改」。发现字段已存在时，明确指出「字段存在、页面未展示」，供需求方判断是否只是展示问题。

### 第五步：收尾三选一

每个目标必须给结论，不能只交一堆文件：

| 结论 | 判据 | 后续 |
|---|---|---|
| 已实现 | 代码或页面实测证实功能存在 | 转「确认现状 + 差异补齐」 |
| 未实现 | 定位成功且确实没有该能力 | 走正常开发流程 |
| 环境不可判 | 仓库未检出、环境不可达、证据不足 | 登记待确认，补充线索 |

证据分级：高（截图 + DOM 或代码锚点）、中（代码锚点）、低（文本推断）。低等级证据不能单独支撑「已实现 / 未实现」结论。

## 示例

**示例一：页面加一列**

目标：功能号 f10546，意图「确认接口返回字段」。

定位到页面 `views/query/multiAcctInfo/index.vue` 与 `template.js`，后端 `F10546Controller`、`F10546ServiceImpl`、`F10546Output`。读 `outputConfig` 发现返回字段里已有 `rival_code`，但输出列配置没有它。结论：字段已存在、页面未展示，属展示层缺口，不需要改接口。

**示例二：确认查询逻辑**

目标：路由 `/query/position`，意图「确认查询逻辑」。

从路由定位页面组件，顺接口调用找到 Controller，再进 Service，看到查询按「客户号 + 交易日期」过滤，DAO 走索引。发现日期为空时退化为全表扫描。结论：已实现；风险是空日期全扫，写入关键发现。

## 完成验证

- [ ] 每个目标都有定位结果：功能号、路由、模块、页面文件、后端文件。
- [ ] 每个结论有 `文件路径:行号`。
- [ ] 读取深度与 `check_intent` 匹配，没有无目的全仓检索。
- [ ] 摘要包含页面配置、后端逻辑、关键发现三段。
- [ ] 每个目标都有三选一结论与证据等级。
- [ ] 未检出项写明了检索范围与待补线索。

## 常见踩坑

- **只读页面不读后端**：看到页面没展示就判「未实现」，实际接口已返回字段。至少读到 Output 类再下结论。
- **把推断当事实**：命名相似就认定是同一功能，没有调用链证据。相似只能是线索，不能是结论。
- **未检出等于不存在**：仓库没检出、分支不对、功能号变更，都会导致检不到。检不到只能给「环境不可判」。
- **读全仓不收敛**：没有目标就全文检索，命中几百个文件，最后无法收敛。先定位再读。
- **忽略配置层**：只读 `index.vue`，漏了 `template.js` 里的输出列、筛选、按钮配置，结论会偏。
- **引用不给行号**：只写文件名，复核时找不到位置。每条结论都要带行号。
- **把环境问题当功能证据**：白屏、404、空白页只说明环境有问题，不能说明功能不存在。
