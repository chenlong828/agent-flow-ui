# REQ-0019 运行实例同源接入与发起运行（B4）

| 字段 | 内容 |
|---|---|
| ID | `REQ-0019` |
| 类型 | `feature` |
| 场景叙述 | 运行观察者进入运行实例列表，看到后端真实运行的状态、工作流、执行节点与耗时；从列表发起运行，选择工作流、已绑定执行节点的 Harness、填写工作区绝对路径并用所见即所得编辑器写启动意图；进入详情查看轨迹与节点状态，双击节点在 90% 视口弹层中查看按 Markdown 渲染的节点消息，对等待人工确认的节点批准或驳回、对进行中的运行终止、下载执行节点上传的会话日志。 |
| 价值 | 没有同源运行视图，运行实例只能停在 MOCK 演示：无法发起、观察、终止或审批真实运行，B4 的运行编排能力在 UI 上没有入口；B3 定义的流程也无法从界面真正跑起来。 |
| 非目标 | 不做暂停/恢复、节点重试、从节点重跑、输入输出与工作区文件留痕、fan-out 子任务下钻（后端未提供端点）；不做 `split`/`fanout` 的启动执行（后端第二期）；不做运行历史版本回放与冻结图快照渲染；不做运行编排鉴权；不改 BFF 转发策略。 |
| 约束 | 运行两页 live-only，经同源 BFF 消费 B4 `/api/v1/runs` 与 `/api/v1/workflows/{id}/runs`，不回落 MOCK；状态机与节点推进由后端决定，页面不推断；发起运行必须选 `enabled && clientId` 的 Harness、绝对工作区路径与非空意图；后端未提供的能力入口置灰并注明；不新增运行时依赖（意图编辑器复用已准入的 Milkdown 7.7.0；节点消息渲染走自带 `shared/markdown`，先转义后出标签、链接白名单）。 |
| 影响场景 | `SCN-0004`（`design/scenarios/operations/instances/control-instance/scenario.md`，verified 5/5） |
| 澄清记录 | 2026-11-12 用户两问确认：范围为运行实例 + 工作流编辑器节点类型；后端缺失能力保留按钮但置灰。同日实现并落 `works/2026-11-12-run-live-integration`（原挂 `REQ-0004`）。2026-11-13 用户要求为新能力单独立卡并补建工序、提交推送；本卡承接，`REQ-0004` 标记 `superseded_by`。2026-11-17 运行实例详情不再使用右侧面板，改由 `REQ-0020` 承接（双击节点打开 90% × 90% 弹层，移除节点消息二次「全屏」）；`SCN-0004` 断言同步更新并复跑 5/5。 |
| 状态 | `delivered`（2026-11-13；`SCN-0004` verified 5/5；2026-11-17 节点详情改双击 90% 弹层，5/5 复跑） |
