# REQ-0029 发起运行时以图片作为初始资料（提交时上传）

| 字段 | 内容 |
|---|---|
| ID | `REQ-0029` |
| 类型 | `feature` |
| 场景叙述 | 研发人员在「发起运行」弹窗里除了填写 Markdown 启动意图，还可以从剪贴板粘贴、拖放或选择一张或多张图片（PNG/JPEG/WebP/GIF）。图片先只存在于浏览器内存，显示缩略图与计数，提交前可自由删除；点「发起运行」时才逐张上传并立即以 `inputId` 绑定本次运行。上传或启动失败时，已上传的暂存项被删除、本地图片保留，用户可直接重试。运行详情显示本次运行的「初始资料（N）」缩略图，可打开原图查看。 |
| 价值 | 纯文本启动意图无法承载截图类资料；用户只能把图片另行放入工作区再写路径，或手写成文字。启动前就上传又会让「选错图/放弃提交」留下服务端暂存垃圾（暂存不设 TTL）。把上传推迟到最终提交，用户能零成本反悔，同时保留图片进入 task-space 的完整链路。 |
| 非目标 | 不做通用文件（PDF/docx/代码）、不做图片编辑/压缩/OCR/重排、不做断点续传与上传队列持久化、不做运行结束后的图片归档浏览、不新增灯箱或第三方依赖、不改后端契约与 BFF 白名单、不改 client 能力协商。 |
| 约束 | 只接受 `image/png`、`image/jpeg`、`image/webp`、`image/gif`（服务端按魔数复验，不接受 SVG）；单张 ≤8 MiB、最多 8 张、合计 ≤20 MiB，UI 本地先校验、服务端为准；提交前不得发任何上传/删除请求；上传并发 ≤3，顺序 = 添加顺序；任一上传或启动失败都必须 DELETE 已上传的暂存项并保留本地图片可重试；启动成功后不得 DELETE 已绑定项；关闭弹窗中止在途请求并释放 object URL；上传途中关闭/崩溃可能留下服务端孤儿（无 TTL），需运维清理；运行详情只读展示，不改变确认/决策语义；`run/data` 仍是 B4 唯一入口，页面不得直接 `fetch /api/v1/run-inputs`。 |
| 影响场景 | `SCN-0024`（新建，验收证据）；`SCN-0004` 发起运行步骤补一句「可添加图片，提交时上传」的描述同步，不新增断言 |
| 澄清记录 | 2026-11-19：调度层交付 `ui-proposal.md`（粘贴即上传）；用户裁决改为**提交时上传**，以便在 web 端提交前删除。同日确认启动失败处理为「立即 DELETE 已上传暂存、保留本地图片供重试」。交付范围 = UI 实现 + 需求/工序文档，提案落在本仓库工序目录、不回写调度层。 |
| 状态 | `delivered`（2026-11-19；`SCN-0024` 6/6、`SCN-0004` 16/16 回归、`npm run test:gate` 通过） |

## 跨仓库说明

调度层 `agent-flow-orchaster` 的 `REQ-0003` §4 仍写「上传采用『粘贴即上传』的暂存模式」。本需求不改变服务端契约（上传时机对 `POST /run-inputs` + `inputs[{inputId}]` 不可见），但调度层需求约束需同步，否则两份现行文档在上传时机上冲突。
