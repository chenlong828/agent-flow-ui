# 坑档案

每条坑三个必填字段：**现象**（观察到什么）、**存续条件**（什么前提下坑仍然存在；已消失的写明消失判定与实证日期）、**对策落点**（现行文档中的防御位置）。已消失的坑保留条目是为了防止同类问题复发时重踩。本档案聚焦本次开发周期（高保真原型 + WebKit 引擎验证）实际踩过的坑；「CSS 遇到的问题」集中在前半部分。

## CSS 类

### CSS-1 · z-index 不配 position 完全不生效（弹层画在遮罩下面）
- **现象**：所有弹窗打开后，页面整体被暗色遮罩盖住，弹窗内容被压在遮罩之下、无法点击，鼠标一点整个界面就退回。用户原话：「弹层之后有一个全部颜色变暗的背景似乎弄到最上层了……所有弹层情况均如此」。
- **根因**：`.modal` 只有 `z-index: 220` 而没有 `position`，z-index 对非定位元素无效；同层叠上下文里遮罩 `.overlay` 是 `position: fixed; z-index: 200`，于是稳赢。
- **存续条件**：永久成立（CSS 规范行为，所有引擎一致）。已修复（2025-10-14）：`.modal { position: relative; z-index: 220 }`。
- **对策落点**：`assets/css/main.css` 层级注释表；《调试方案》第 3 节命中测试断言（jsdom 查不出此类问题，必须引擎层验证）。

### CSS-2 · inset 简写属性在旧版 Safari 不支持
- **现象**：用 `inset: 0` 的元素在旧 Safari 上没有定位效果（层不铺满、错位）。
- **存续条件**：Safari < 14.1。用户环境含旧 Safari 时坑仍在。
- **对策落点**：`assets/css/main.css` 中 `.switch i`、`.overlay`、`.modal-wrap` 全部改写为显式 `left: 0; top: 0; right: 0; bottom: 0`。新增全屏定位层沿用显式四边写法。

### CSS-3 · html 级 CSS zoom：计算值存在，布局无视，且部分实现扭曲 fixed 包含块
- **现象**：Playwright WebKit（构建 2104）中，给 `<html>` 设 `style.zoom = 1.538`：所有元素（流内与 fixed）的渲染尺寸**完全不变**，但 `getComputedStyle` 返回 `zoom: 1.538`；更隐蔽的是 fixed 元素的包含块（视口）**按 zoom 比例缩小**（1440px 视口下弹窗容器只有约 936px），导致居中的弹窗被 flex-shrink 压扁（1152px 请求只渲染 899px）并偏向左侧。
- **存续条件**：仅该 WebKit 构建；真实 Safari 的 zoom 实现未在本环境验证（无法 sudo 启用 safaridriver）。**在完成真实 Safari 探针验证之前，必须假定两条路径都可能走到**。
- **对策落点**：《调试方案》第 5 节探针法；`assets/js/ui.js` `applyZoom()` 双路径（探测生效用 zoom，失效清除 zoom 并以 transform 缩放外壳）。**遗留验证项**：在真实 Safari 上跑探针确认 zoom 路径行为。

### CSS-4 · position: fixed 的祖先带 transform → 包含块变更为该祖先
- **现象**：fixed 元素不再相对视口定位，而是相对带 transform 的祖先。
- **存续条件**：永久成立（规范行为，属于认知坑）。
- **对策落点**：本项目的字体缩放兜底方案**有意利用**此行为（transform 缩放 `.topbar` 与 `#df-layout` 时，弹层保持挂在 body 下不受影响）。反向提醒：给任何包含 fixed 子元素的容器加 transform/animation 前先检查层级结构。

### CSS-5 · flex 子项默认可收缩，固定宽度请求会被压扁
- **现象**：弹窗在缩水后的弹窗容器（见 CSS-3）内被 flex-shrink 压到比请求宽度小，且居中位置偏移。
- **存续条件**：容器小于子项请求宽度时必然发生。
- **对策落点**：`assets/css/main.css` 关键面板无 flex-shrink 依赖；排查「宽度不对」时先看父容器实际宽度再怀疑子项样式。

### CSS-6 · 视口单位与缩放叠加的语义歧义
- **现象**：`80vw`、`96vw` 这类宽度在存在缩放（zoom 或 transform 兜底）时，"视口的百分之八十"究竟是换算前还是换算后，各引擎不一致。
- **存续条件**：任何使用缩放方案的界面，永久需要面对。
- **对策落点**：`assets/js/ui.js` `DF.modal.open` 的 `resolveW()`——字符串宽度在 zoom 路径下除以缩放系数换算为像素，兜底路径下不换算；规则集中在这一处，新增宽度逻辑必须走它。

## JavaScript / DOM 类

### JS-1 · 弹层页脚按钮以 body 为根查找 → 打开即抛错
- **现象**：弹窗一打开就 `TypeError: null is not an object`，页脚按钮全部失效。涉及专家、技能库、工具、实例等多个页面共 9 处。
- **根因**：页脚按钮在 `.d-foot`（`.d-body` 的兄弟节点）里，`body.querySelector('#xxx')` 查不到。
- **存续条件**：已全部修复（2025-10-14，统一为 `closest('.modal') / closest('.drawer')` 作用域）。批量生成页面时可能复发。
- **对策落点**：《代码重构要点》第 1 节规则 2；子代理提示词内嵌的绑定规则。

### JS-2 · 页头操作按钮静默不绑定
- **现象**：「新建工作流」按钮渲染正常、点击毫无反应、无任何报错（`querySelector` 返回 null 后绑定语句形同虚设——取决于写法，本次是作用域查找落空）。
- **根因**：页头 `.acts` 是 `#page-body` 的兄弟节点，以页面主体为根的查找永远够不到。
- **存续条件**：已修复（改为 `document.getElementById`）。凡新增页头按钮，复发风险与页头结构同寿。
- **对策落点**：《代码重构要点》第 1 节规则 1。

### JS-3 · DF.modal.confirm 先关闭后解析 → 任何按钮都返回 false
- **现象**：确认框点「确定」也得到 false，业务操作（删除等）全部静默取消；叠加按钮查找 null 直接抛 TypeError，确认框从未成功 resolve 过。
- **存续条件**：已在 `assets/js/ui.js` 修复（settled 标志 + `closest('.modal')` 作用域，2025-10-14）。保留条目防止重写时再犯。
- **对策落点**：《代码重构要点》第 4 节（confirm 是共享能力，不要在页面重造）。

### JS-4 · 平行函数间的闭包变量断链（doms / cur）
- **现象**：选中编辑器的专家节点后抛 `ReferenceError: Can't find variable: doms`，进而导致节点拖拽完全失效（拖拽处理器在选中阶段就崩了）；同类问题还有 `cur`。
- **根因**：渲染函数 `agentInspector(n)` 与绑定函数 `bindAgentInspector(n)` 是平行函数，绑定函数引用了渲染函数的局部 const。
- **存续条件**：已修复（绑定函数自取数据，2025-10-14）。函数拆分时会复发，`node --check` 与语法冒烟均查不出。
- **对策落点**：《代码重构要点》第 2 节。

### JS-5 · innerHTML 赋值覆盖此前 appendChild 的节点
- **现象**：弹窗拖宽把手（`.rz-l` / `.rz-r`）不存在，测试报找不到元素。
- **根因**：把手先 `appendChild`，随后 `m.innerHTML = '...'` 把整个内容连同把手清掉重建。
- **存续条件**：已在 `ui.js` 修复（先 innerHTML 后挂把手）。构建复合 DOM 时会复发。
- **对策落点**：《代码重构要点》第 3 节。

### JS-6 · 布尔变量误当函数调用（语法检查查不出）
- **现象**：拖宽把手按下即抛 `TypeError: zoomOnFixed is not a function`，拖拽无声失效。
- **根因**：ui.js 同一作用域里 `zoomOnFixed` 是布尔标志，导出的才是访问器函数；模块内误加调用括号。
- **存续条件**：已修复（2025-10-14）。模块内直读标志、导出时包函数的命名模式会持续诱发。
- **对策落点**：《调试方案》引擎层冒烟（行为断言能抓住"拖拽无效"）；命名约定：标志与访问器不要同名。

### JS-7 · 右缘坐标误用左缘防溢出公式 → 锚定菜单整体推偏（命中测试仍通过）
- **现象**：2026-10-13 顶栏用户区下拉（右缘锚定语义）右缘与触发器差 8px（默认字号）／25px（最大字号兜底缩放）；`elementFromPoint` 命中测试全部通过——**位置偏差只有位置断言抓得住，命中测试抓不住**。
- **根因**：`DF.menu` 的 `opts.alignRight` 分支把右缘坐标 x 套了左缘语义的钳制公式 `min(x, innerWidth - width - 8)`，贴屏幕右缘的锚定菜单被整体左推；已改为"先钳右缘坐标入视口、再减实际宽度"（`min(x, innerWidth - 8) - offsetWidth`）。
- **存续条件**：按右缘语义传 x 的新调用方复用默认左缘钳制分支即复发；x 语义两分支的约定写在《代码重构要点》§4。
- **对策落点**：《代码重构要点》§4 `DF.menu` 条目（两分支语义）；《调试方案》§4 规则五（断言位置前先确认 x 语义）。

### JS-8 · 程序化 el.click() 无坐标 → clientX 起源的弹层画到屏幕最左
- **现象**：2026-10-13 引擎层回归中，`b.click()` 触发「更多」菜单后断言"菜单不在按钮附近"（左缘差 483px）——真实用户点击无此问题，是测试事件缺坐标（`clientX = clientY = 0`），页面代码无缺陷。
- **根因**：程序化 `el.click()` 派发的点击不带坐标；以 `e.clientX` 为定位起源的组件（`DF.menu` 旧调用方）按 0 定位。
- **存续条件**：测试脚本用 `el.click()` 验证 clientX 起源的弹层时必然发生；真实用户点击不受影响。
- **对策落点**：《调试方案》§4 规则四（必须派发带坐标的 `new MouseEvent('click', { clientX, clientY })`）。

## 接口契约类

### API-1 · BFF 请求头白名单漏掉条件请求头 → 文档永远拿不到 304
- **现象**：绕过 BFF 直连 B1，文档第二次带 `If-None-Match` 返回 304；经 `:3000` BFF 访问始终 200，`ETag` 看似存在但条件请求不生效。
- **根因**：BFF 只复制 `REQUEST_HEADERS` 白名单内的请求头，旧白名单没有 `if-none-match`，条件头在上游请求前就被丢弃；上游只能按无缓存请求返回完整文档。
- **存续条件**：任何新增协商/条件请求头（如 `If-Modified-Since`、`Range`）未加入 `REQUEST_HEADERS` 即复发。已修复（2026-10-26 加入 `if-none-match`，BFF 单测覆盖 200/304）。
- **对策落点**：`bff/index.js` 的 `REQUEST_HEADERS`；`tests/bff/bff.test.js` 文档 200/304 用例；`docs/design/components/bff/spec.md` 请求头/响应头表。

## 工具链 / 环境类

### ENV-1 · 无头 Chrome 在本机启动即崩溃
- **现象**：报 `Failed to create headless user data directory container`，随后进程 Trap。
- **存续条件**：本机环境，持续存在。**不要再用 Chrome 做自动化**。
- **对策落点**：`docs/design/dev-environment.md` 第 3.3 节；统一用 Playwright WebKit。

### ENV-2 · Playwright WebKit 构建包直连与镜像均 404
- **现象**：`npx playwright install webkit` 反复失败。
- **存续条件**：该 CDN 路径仅代理可达；升级 Playwright 后构建号变化，需按新报错重新取构建号。
- **对策落点**：`docs/design/dev-environment.md` 第 3.2 节（代理手动下载 + INSTALLATION_COMPLETE 完整步骤）。

### ENV-3 · npm 默认缓存目录被屏蔽
- **现象**：npm 安装报缓存目录权限错误。
- **存续条件**：持续存在（~/.npm 被屏蔽是本机策略）。
- **对策落点**：`docs/design/dev-environment.md` 第 3.2 节（`npm_config_cache` 重定向）。

### ENV-4 · Playwright 合成鼠标事件与页面命中测试在缩放下坐标系不一致
- **现象**：`page.mouse` 按坐标派发，页面收到的 mousedown 目标全是 `<html>`，拖拽完全无效；无缩放时一切正常。
- **存续条件**：页面存在 zoom / transform 缩放时必然发生（该 WebKit 构建实测）。
- **对策落点**：《调试方案》第 4 节——页面内程序化 MouseEvent 派发 + scrollIntoView 先行。

### ENV-5 · 用户侧 Safari 陈旧缓存导致"页面不显示"类报告
- **现象**：用户报编辑器页面打不开；同源引擎实测渲染正常，判定为浏览器缓存了旧资源。
- **存续条件**：只要静态资源无版本化文件名（当前无），永远可能发生。
- **对策落点**：《调试方案》第 6 节响应流程（强刷优先）；长期对策是给静态资源加版本参数，当前原型阶段未做。

### ENV-6 · jsdom 24 在 window.close() 后取不到 DOM
- **现象**：冒烟脚本先 `dom.window.close()`、再读 `dom.window.document.getElementById('app')`，抛 `Cannot read properties of undefined (reading 'getElementById')`，12 页全判失败。
- **根因**：jsdom 24 关闭后 `window` 被置空；断言与取样必须在 close 之前完成。
- **存续条件**：只要沿用「先 close 再断言」的写法就会复发；jsdom 24.1.3 实测。
- **对策落点**：`tools/smoke-test.js` 在 close 前取 `app` 存入变量再断言；《调试方案》第 2 节模板同理。

### ENV-7 · 后端进程未重启，代码/迁移已更新但接口仍报 500
- **现象**：Skill 列表与专家列表返回 500 `internal`，文档路由对合法 UUID 返回 404「路径不存在」；同一仓库新起 3101 进程后同一数据库读写正常。
- **根因**：运行中的 3100 是旧进程/旧路由，数据库已按新迁移删除旧列；旧代码查询已删列或没有新端点，于是 500/404。
- **存续条件**：后端代码、路由或迁移更新后未重启常驻进程即复发；与页面和 BFF 无关。
- **对策落点**：验证前先探测 `/healthz`、新端点与列表响应；重启后端或另起临时端口验证，不把旧进程的 500 当成前端缺陷。2026-10-26 用 3101 + 3002 完成真实读写验证，未重启用户的 3100。

## 流程类

### FLOW-1 · 子代理批量生成页面时上下文耗尽
- **现象**：一份提示词要求生成 2–3 个页面的子代理全部耗尽上下文，没有产出任何文件。
- **存续条件**：提示词过重时必然复发。
- **对策落点**：《代码重构要点》第 7 节（单页单代理 + API 速查内嵌；最重页面主笔）。

### FLOW-2 · 测试脚本自身的坐标与作用域错误伪装成页面缺陷
- **现象**：多轮"修复"实际是在修测试脚本：Node 作用域变量误用在页面上下文、把手点击点取在元素盒边界外、断言选错弹窗、忘记先设缩放档位就断言缩放结果、拖拽起点在视口外。
- **存续条件**：永久性风险（写测试就会犯）。
- **对策落点**：《调试方案》第 4 节规则三的排查顺序。
