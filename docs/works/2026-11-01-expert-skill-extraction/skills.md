## 1. 拆分规则

### 1.1 硬约束（来自 B1 契约）

- `SKILL.md` 新建草稿预留 **16 KiB**；超出即保存失败。
- 附件放 `references/` 或 `scripts/`，单文件 0–20 MiB，附件 ≤99 个，整包 ≤100 MiB。
- 附件只读展示，不参与详情页正文渲染；正文必须自足，引用是「展开阅读」。

### 1.2 什么时候拆 reference（5 条判据）

1. **单节超过 4 KiB**：规则表、检查清单、字段表，整段移出，正文留三行摘要 + 链接。
2. **两套规则并存**：UFT 与 ARES、新增接口与消费既有接口，各拆一个文件，避免正文二选一。
3. **完整示例 ≥3 个**：示例移入 `references/0x_示例.md`，正文只留 1 个最小例。
4. **machine-readable 契约**：schema、findings 格式、frontmatter 模板，放 `references/`。
5. **脚本说明超过 1 KiB**：参数/退出码/示例移到 `scripts/README.md`，正文只写「怎么调」。

### 1.3 正文必须留什么

- 适用场景 / 触发词 / 不适用（`description` ≤400 字，正文再展开一句）。
- 3–7 步主干（每步：输入 → 动作 → 产物）。
- 完成验证（可判定项，≤6 条）。
- 2–4 条踩坑（来自来源仓的禁止事项）。
- 1 个最小示例。
- 参考资料索引（路径 + 一句话说明，不复制内容）。

### 1.4 命名与引用

```text
sk-xxx/
├── SKILL.md
├── references/
│   ├── 01_xxx.md      # 规则/清单
│   ├── 02_xxx.md      # 示例/判定树
│   └── 03_xxx.md      # 契约/schema
└── scripts/           # 可选，演示不执行
```

引用统一写相对路径 `references/01_xxx.md`；正文「参考资料」节只列文件名与用途。
