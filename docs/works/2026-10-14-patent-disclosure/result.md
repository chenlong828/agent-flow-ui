## 核心欲保护点（蒸馏结论）

1. **代码化编排器（无 LLM 调度）**：顺序调度/评审判定/回退控制/数千级并行拆分聚合/状态机全部确定性代码；
2. **工作区唯一信息信道**：节点独立上下文 + git/共享文件工作区为唯一通道（标准目录模板 + worktree 隔离 + 留痕）；
3. **配置扮演的最小节点集**：五类节点 + 三类边表达 Re-act 循环/意图路由/人工门禁/大规模并行，静态校验收敛；
4. **评审判定边界语义**：独立否决视角 + 唯一固定回退目标 + 评审意见经工作区结构化传递；
5. **清单驱动 fan-out/fan-in**：代码化拆分 + 独立上下文/独立 worktree + 并发上限/配额 + 三种聚合策略；
6. **四类资产注册体系**：专家（固定+变动）/ Skill（渐进披露+禁令+版本）/ Harness（标签+心跳+配额）/ 工具（注册→调试→可用）；
7. **节点级上下文与收敛配置**：分层知识索引注入 + SVO 锚点 + 收敛约束 + 工具最小权限；
8. **双闭环治理**：运行闭环（评审回退）+ 治理闭环（Skill 审计：被跳过/自我冲突/老化 + 知识索引更新工作流）。

## 检查限制（如实记录）

- `check_office.py` 通过 = ZIP/XML 完整性、内嵌关系、段落/表格/分节结构核验；**分页、裁切、字体渲染等视觉排版未逐页目检**（当前会话模型不支持读图，按 office-docx 技能规则以结构 + 内容断言收口）；建议 Word 打开走查一遍附图页面；
- 附图由脚本绘制，为**示意性质**：正式申请附图可按 §9 清单重绘（`draw-figures.py` 可作为布局底稿）；
- 发明名称、权利要求建议措辞为**整理稿**，最终以专利代理人撰写的申请文本为准。
