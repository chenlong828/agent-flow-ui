# 列表分页统一提案（待裁）

> 提交对象：调度层（`plan/roadmap.md` 候选批次 + `plan/open-questions.md` OQ-9）。
> 状态：提案，未排期。用户 2026-11-12 指示「分页暂时不增加，以后再做」。

## 1 结论先行

- **能力已在后端，前端只用了一页**：B1（Harness / 工具 / Skill / 专家）、B3（工作流）、B4（运行实例）的列表端点都返回 `{items,total,limit,offset}`，后端默认 50、上限 200；前端除工作流列表外都固定 `limit=200` 一次取全量。
- **真正的风险是静默截断**：超过 200 条后，记录不会出现在任何一页，搜索也搜不到；Harness 统计卡的「总数」取 `page.total`，会出现「总数 300、表格只有 200 行」。
- **建议**：按「服务端分页 + 统一分页器」分三批推进，先做数据增长最快的运行实例 / 工具 / Skill；MOCK 三页已默认关闭（`REQ-0018`），其分页随解禁或 live 化再做，不占本轮。

## 2 现状核查

| 页面 | 数据入口 | 当前取数 | 筛选/排序位置 | 分页 |
|---|---|---|---|---|
| 运行实例 | `run/data` + `workflow/data` | `/runs?limit=200`、`/workflows?limit=200`，页面侧 join 工作流名 | 状态 Tab 按已加载集合分组 | 无；>200 截断 |
| Skill 库 | `API.list('skill')` | `limit=200&sort=updatedAt:desc` | 分类 / 标签 / 搜索均在页面 `filter` | 无；分类计数也只覆盖已加载集合 |
| 专家管理 | `API.list('expert')` | `limit=200` | 搜索 / 启停状态在页面过滤 | 无 |
| Harness 管理 | `API.list('harness')` | `limit=200` | 无筛选；统计卡用 `page.total` | 无；行数可能小于总数 |
| 工具与集成 | `API.list('tool')` + harness | `limit=200` | 类型 / 状态 / 搜索在页面过滤 | 无 |

| 详情内嵌列表 | 各自页面 | 专家选择器 `limit=200`；实例节点取 `run.nodes` | 页面过滤 | 无 |

## 3 后端契约事实（已核对）

- `kernel/pagination.ts`：`Page<T> = {items,total,limit,offset}`；`DEFAULT_PAGE_LIMIT=50`、`MAX_PAGE_LIMIT=200`；非法 `limit/offset` 抛 `ValidationError`。
- 各列表均已接分页：`GET /harnesses|/tools|/skills|/experts|/workflows|/runs`；`/runs` 支持 `workflowId`、`state`；工作流支持 `q/type/sort`；Skill 支持 `q/category/tag/enabled/sort`。
- 前端不需要新增后端能力；需要逐列表确认的是**筛选参数是否齐全**与**排序口径**（尤其专家启停、工具状态、Harness 健康）。

## 4 方案选项

| 方案 | 做法 | 优点 | 代价/风险 |
|---|---|---|---|
| **A 服务端分页 + 统一分页器（推荐）** | 页面把 `q/筛选/排序/offset/limit` 下推；新增 `DF.pager`；`total` 驱动页码 | 真正解决 >200 截断；搜索/统计覆盖全量；与工作流列表一致 | 每个列表要改查询与筛选；需逐项核对后端筛选字段；测试量最大 |
| B 前端分页 | 仍取 200 条，只切页 | 改动最小，视觉统一 | >200 仍丢失；搜索仍不全；只是把问题藏起来 |
| C 仅补分页器 | 不改取数，只加分页控件 | 过渡快 | 无实际收益，容易误导「已支持分页」 |

**推荐 A**，理由：后端契约已就绪，B/C 不解决真实数据丢失，反而增加后续返工。

## 5 影响面与契约

- 公共件：新增 `DF.pager`（`CMP-ui-shell` 原语）——输入 `total/limit/offset`，输出「第 x–y 条 / 共 n 条」、上一页/下一页（是否加页码见 §7），与工作流列表现有分页统一；`DF.NAV` 不变。
- 数据层：`API.list` / `run-data.list` / `workflow-data.list` 已透传 query，不改签名；页面把筛选参数下推，不在浏览器内 `filter` 全量。
- 页面：运行实例、Skill、专家、Harness、工具 5 个组件；工作流列表只换分页器外观（行为不变）。
- 测试：每个列表 3 正 1 反（首页、翻页、筛选后回第 1 页、越界/末页），沿用 `tools/verify-m1-scenarios.js` 或独立 runner；`smoke-test` 保持 13 页。
- 文档：5 个组件规格补分页契约；`architecture.md` 登记 `#pager`；场景新增/修订对应 SCN。

## 6 建议批次（待裁后排期）

| 批次 | 内容 | 理由 | 规模 |
|---|---|---|---|
| 批次 1 | 运行实例、工具、Skill 库 | 数据增长最快；筛选字段后端已支持 | 3 个 `change` 任务 + 1 个 `verify` |
| 批次 2 | 专家管理、Harness 管理 | 卡片/统计口径需单独确认（总数、启停计数） | 2 个 `change` + 1 个 `verify` |
| 批次 3 | 工作流列表换统一分页器；详情内嵌列表（专家选择器） | 行为不变，收口视觉与 200 上限 | 2 个 `change` |
| 暂缓 | MOCK 三页本地分页 | 页面默认关闭，等解禁或 live 化 | — |

每批独立验收，不一次性铺开；组件级 WIP=1 仍适用。

## 7 待裁定（提交 OQ-9）

1. 每页条数：固定 20、固定 50，还是 20/50 可切换？
2. 分页器形态：仅「上一页 / 下一页」，还是带页码跳转？
3. 筛选变化后是否回到第 1 页、页码是否写入 URL（可分享/刷新保留）？
4. Skill 分类计数、Harness 统计卡等「总数」是否统一以 `total` 为准（全量 count，而非当前页）？
5. 运行实例的工作流名 join 是否改由后端返回 `workflowName`，避免再拉 200 条工作流？

## 8 验收口径（裁定后写入 REQ/SCN）

- 每个列表 `total` 与后端一致；>200 条可翻到全部记录。
- 筛选/搜索/排序下推后结果正确；切换筛选回到第 1 页；越界页回到最后一个有效页。
- 空态、错误态、加载态与现有页面一致；不回落 MOCK。
- 5 个列表各 3 正 1 反通过；工作流列表行为不回归；13 页冒烟通过。

## 9 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 后端筛选字段不齐 | 某些页面当前靠前端过滤，后端未必支持同名参数 | 批次 1 前逐端点核对 `http-gateway` 契约，缺口先补后端或降级为「仅分页、筛选仍前端」并登记 |
| 统计口径 | 统计卡可能按当前页计算 | 统一改为 `total` 或明确「本页合计」文案 |
| 测试成本 | 5 个列表 × 4 条 + 跨页联动 | 按批次验收，先做纯逻辑查询测试，再上 Playwright |
| 页码与筛选状态 | 刷新/分享后状态丢失 | 先内存态，URL 方案单列裁定（§7.3） |
