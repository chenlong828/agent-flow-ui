# 运行实例（列表 + 详情）

> 导航：运行与运营 / 运行实例　|　形态：列表页 + 独立详情二级页　|　前置：`design/components/ui-shell/spec.md`

## 0 模块卡

> 追溯：`REQ-0004` / `SCN-0004`（verified；DOM/jsdom 3 正 1 反）。

- 状态：active
- 单元 / 层：组件 / L2 页面组件（列表 + 详情两个页面入口）
- 业务价值：为运行观察者与操作者提供实例进度、节点轨迹、等待人工确认与异常控制；没有它，工作流只能被定义，无法被观察、干预或留痕。
- 负责 / 不负责：负责实例列表（状态 Tab/统计/进度/耗时）、详情页（流程轨迹、节点输入输出与留痕、fan-out 聚合与抽样明细）、发起运行/暂停恢复/终止/节点重试/从节点重跑/人工批准驳回；不负责工作流定义与画布编辑（`CMP-workflow-editor`）、专家/Harness/工作区等资产定义（各自组件）、外壳（`CMP-ui-shell`）。
- 数据所有权：读 `MOCK.instances`、`MOCK.workflows`、`MOCK.workspaces`、`MOCK.experts`、`MOCK.harnesses`；写 `MOCK.instances`（发起运行 `unshift`、节点状态迁移、暂停/恢复/终止、重试计数、人工批准/驳回，仅内存态，刷新复位）；sessionStorage `df-new-instance` 用于列表页向详情页一次性传递新建实例；无第二写入口说明：实例集合仅本组件写，其余页面只读。
- 公开契约：页面入口 `pages/instances.html` 与 `pages/instance-detail.html?id=<instanceId>`；操作 `CMP-instances#list`、`#start-run`、`#pause-resume`、`#terminate`、`#retry-node`、`#approve-reject`；不变量 实例状态只取「运行中/等待人工确认/回退重跑中/已暂停/成功/失败/已终止」；列表的「已结束」是成功/失败/已终止的聚合 Tab，不是独立状态；终止为不可逆终态，暂停可恢复；等待人工时批准与驳回互斥，驳回必须携带意见；fan-out 聚合统计（成功/失败/运行中/重试中）与子任务明细同源；节点停止后不得继续推进。
- 依赖：`DF`（外壳、弹窗、表格、Tabs、Toast、时间格式化）/ `MOCK`；不依赖其他页面组件（跨页只走 URL 与 `df-new-instance`）。
- 变化轴：实例/节点状态机与控制语义（暂停、终止、重试、重跑、人工驳回）最易变，新增状态须同步列表、详情、控制按钮与留痕。
- 验证入口：`npm start` + `/pages/instances.html`、`/pages/instance-detail.html?id=INS-2041`；`node tools/smoke-test.js`（全站冒烟，含两页）；SCN-0004（verified，3 正 1 反；`node tools/verify-m1-scenarios.js SCN-0004`）。
- 预算：`instances.js` 约 7 KB + `instance-detail.js` 约 18 KB + 本规格约 9 KB，场景断言在 `tools/verify-m1-scenarios.js`；上限 120k token，远低于上限。
- 单独运行：`npm start` → `/pages/instances.html`（详情页用 `?id=` 定位，缺省回落到夹具实例）。
- 删除测试：删除后实例不可观察、不可控制、不可审批，工作流只剩定义；复杂度会集中到工作流列表/编辑器，故保留为独立组件。
- 已知偏差：M1 追溯已补（REQ-0004/SCN-0004），场景 verified（DOM/jsdom 3 正 1 反 40/40）；状态迁移与控制行为已有 DOM 层断言，拖拽/真实调度仍无引擎层断言；`df-new-instance` 的新建实例注入是演示路径，刷新复位；fan-out 数千规模为聚合视图 + 抽样，非逐条真实调度（OQ-6）。

## 1 页面定位

运行中工作流实例的查看与控制：进度监控、异常终止、暂停恢复、节点重试/重跑、留痕查看、人工确认（方案确认由人工确认节点承载，R2）。

## 3 实例详情页（独立二级页）

### 3.1 布局

```
┌────────────────────────────────────────────────────────────────────┐
│ ← 返回 │ INS-2041 · 研发四阶段主流程 v1.2 │ [运行中] 耗时 00:42:10    │
│                      [⏸暂停] [⏹终止] [↺从节点重跑]                    │
├──────────────────────────────────────────────────┬─────────────────┤
│  只读流程轨迹图（复用画布，R4）                       │ 节点详情面板      │
│   [需求获取✓][意图识别✓][评审✓][方案设计●][评审…]      │ 概要|输入输出|日志│
│        ↖──── 回退×1（紫虚线弧）────↙               │ |工作区留痕      │
│   [fan-out ⇉2048]══[fan-in]                       │                 │
│   图例：✓成功 ●运行中 ○待执行 ◇等待人工 ✕失败 ⟲回退    │                 │
└──────────────────────────────────────────────────┴─────────────────┘
```

### 3.2 头部控制区

| 操作 | 交互 |
|---|---|
| 暂停 / 恢复 | 即时生效，状态标签切换 |
| 终止 | 二次确认弹窗（说明进行中子任务将被取消），状态→已终止 |
| 从节点重跑 | 点击历史节点后可用；确认弹窗警示「该节点之后的结果将作废」 |

### 3.3 流程轨迹图（主区，只读）

- 复用编辑器画布渲染：节点状态着色（待执行灰 / 运行中蓝+脉冲 / 等待人工橙 / 成功绿 / 失败红 / 已跳过灰斜纹 / 触发回退紫描边）
- 回退弧线紫色虚线 + 「回退×N」标注；fan-out 展开带显示子任务规模
- 点击节点 → 右侧面板联动；当前节点自动居中

### 3.4 右侧节点详情面板（Tab 切换）

| Tab | 内容 |
|---|---|
| 概要 | 节点名/类型、专家（头像+名）、Harness、开始/结束时间、耗时、重试次数；顶部快捷操作：失败节点 [重试]；历史节点 [从此节点重跑] |
| 输入与输出 | 输入=读取的 workspace 路径列表+摘要；输出=产物路径+变更文件列表+增删行数统计 |
| 执行日志 | 模拟日志流（时间戳/级别/内容），自动滚动，支持按级别过滤 |
| 工作区留痕 | 变更文件树 + 每文件 diff 摘要；链接跳工作区详情 |

### 3.5 特殊节点面板

| 节点 | 专属内容 |
|---|---|
| fan-out 节点 | 统计卡（总数 2048/成功/失败/运行中/重试中）+ 状态分组表 + 抽样明细 50 条分页（子任务 ID/输入摘要/状态/耗时）→ **点击行打开子任务详情抽屉（R4）**：独立上下文说明、所属 worktree、日志、Patch 文件列表 |
| 评审节点 | 评审要点、评审意见全文、判定结果（通过→下一节点｜不通过→回退至 X，第 N 次）、对应留痕链接 |
| 人工确认节点（等待中） | 待确认方案内容（来自 workspace 文档预览）+ **批准**（意见选填）/ **驳回**（意见必填，驳回后回退至节点预设目标）按钮；列表页同步消除待确认角标 |

## 4 状态与空态

- 无实例：空态「发起第一次运行」
- 已结束实例：控制按钮置灰，仅保留查看与重跑入口

## 5 模拟数据依赖

`MOCK.instances[]`：8 个覆盖全部状态，字段 `{id,workflowId,version,status,currentNode,progress{done,total},startedAt,duration,nodes:[{id,status,expertId,harnessId,timeline,io,logs,artifacts,review?,confirm?,fanout?}],workspaceId,remark}`；其中 1 个含回退轨迹、1 个等待人工确认、1 个 fan-out 大实例（2048 子任务聚合 + 抽样明细）。
