# 研发智能体工作流编排服务 — UE 原型需求归纳总结

> 版本：v1.0（评审稿）　|　来源：用户需求描述 + `reference/workflow_concept.pptx`（8 页）+ 三轮问答确认 + Google 分析建议裁定
> 下一步：模块拆分 → 页面细化 → 原型页面输出（每步停下评审）

---

## 1. 项目概述

### 1.1 目标

构建一个**研发智能体工作流编排服务的 UE 原型**（Web 控制台形态，高保真可交互，纯前端 + 模拟数据）。编排器是**代码侧的调度与协调者**，Agent 的实际执行由**注册到系统、运行在 Harness 上的专家（智能体）**完成。

### 1.2 核心能力（来自需求描述与 PPT）

| 能力 | 说明 |
|---|---|
| 计划–执行–审视骨架 | 工作流按阶段（需求→设计→开发→集成验证）组织，阶段内按节点顺序驱动专家，对应 PPT 的 Re-act 循环。**不设专门"Re-act 循环节点"**——循环由"专家执行节点 + 评审回退边 + 人工确认节点"通过流程配置扮演 |
| 评审回退 | 评审/校验节点以**独立、否决的视角**输出指令：通过 → 进入下一节点；不通过 → 回退到**预设的固定回退目标节点**，携带评审意见重跑 |
| fan-out / fan-in | 大规模并行展开（可达数千并行子任务），由编排器**代码化调度**（PPT 明确：编排器用 LLM 做大规模调度会退化，必须代码化） |
| 上下文隔离 | 所有节点执行上下文独立，**Workspace（git 仓库/共享文件）是节点间唯一的信息交互与传递通道**，并承担工作数据留痕 |
| 人机协同 | 人工确认节点承载方案确认/人工校准；收敛最终依靠 DevOps 验证（黄金标准），人工与约束只做辅助收敛 |
| 意图路由 | **不设专门路由节点**——按需求类型分流由"入口专家节点 + 不同分支工作流配置"扮演 |

### 1.3 交付形态（已确认）

- **高保真可交互 HTML 原型**：纯 HTML/CSS/JS（原生，无构建步骤），内置模拟数据，可点击走通全部页面与关键交互，无需后端。
- **视觉风格**：浅色企业后台（类 AntD Pro），左侧导航 + 高信息密度表格/卡片；界面语言中文。
- **优先级原则**（R3 澄清）：当前以**演示跑通核心模型**为优先——节点类型、页面均保持精简，引擎级特性仅做配置展示或文档记录。
- **原型边界**：不做真实后端、权限体系、知识库运营机制、CI/CD 触发节点、波谷调度界面；PPT 中的 CICD/业务架构树作为背景集成对象呈现。

## 2. 术语表

| 术语 | 定义 |
|---|---|
| 编排器 Orchestrator | 代码侧调度执行体：顺序调度、评审指令判定、回退控制、fan-out/fan-in 大规模并行调度、实例状态管理、留痕 |
| 专家 Expert | 独立上下文执行的智能体模板 = 角色/性格描述 + Skill 组合 + 工具清单 + 参考知识（PPT P4「固化专家模板」：固定部分 + 任务变动部分） |
| 技能 Skill | 独立沉淀的能力单元：名称、Description（模型路由/触发）、工作内容（渐进披露：流程总述/步骤/脚本指南/完成验证方案）、踩坑记录（严格禁令）、参考引用、版本（PPT P8） |
| 执行设施 Harness | Agent 实际运行处：笔记本 / 台式机 / 服务器 / 容器（PPT P5），提供工具、MCP CLI、代码检索等执行环境 |
| 工具 MCP/CLI | 独立注册的确定性工具资产（调用链分析、Linter、DSL 检索、元数据查询、造数工具等），被专家/Skill 引用，由 Harness 承载运行 |
| 工作区 Workspace | git 仓库或共享文件构成的任务工作集合：Agents.md 总纲、知识库索引、专家库/Skill 库目录、按任务划分的并行工作目录、专家工作群（PPT P8） |
| 工作流 Workflow | 节点 + 有向边的流程定义模板（可复用） |
| 实例 Instance | 工作流的一次运行，含节点运行轨迹、子任务、留痕与控制操作 |
| 节点 Node | 工作流中的执行单元，共 5 类（见 §4.1） |
| 回退 Loop-back | 评审/校验节点不通过时，回到其**唯一预设回退目标**节点重跑，携带评审意见 |
| fan-out / fan-in | 清单驱动的并行展开与聚合（见 §4.3） |
| 人工确认节点 | 流程内等待人工批准/驳回的挂起点，承载「方案确认」「人工校准」 |

## 3. 系统蓝图

```
   人工用户（方案确认 / 校准 / 审视）
        │ 批准·驳回·意见
        ▼
┌───────────────── 编排服务（代码侧，无 LLM）─────────────────┐
│  工作流定义：节点（绑定专家）+ 边（顺序/回退/并行网关）          │
│  编排器：顺序调度 · 评审指令判定（通过→下行 / 不通过→固定回退）   │
│          fan-out 清单拆分与并发调度 · fan-in 聚合 · 状态机管理   │
│  注册中心：专家库 · Skill 库 · Harness 池 · 工具库 ·            │
│            Workspace 配置 · Key                                │
│  实例管理：运行轨迹 · 控制（终止/暂停/重试/重跑）· 留痕查询       │
└───────────────┬──────────────────────────┬─────────────────┘
                ▼ 分发任务                   ▼ 读写（唯一信息通道）
┌────────────────────────┐   ┌─────────────────────────────────┐
│  Harness 执行设施池      │   │  Workspace 工作区（git/共享文件）  │
│  容器 / 服务器 /         │   │  Agents.md · 知识库索引 ·          │
│  台式机 / 笔记本         │──▶│  任务工作目录（多 Agent 并行）·      │
│  运行专家 Agent：        │   │  工作留痕 / 产物                    │
│  Skill 组合 + 工具 +     │   └─────────────────────────────────┘
│  参考知识（独立上下文）    │
└────────────────────────┘
```

**编排器代码侧职责**（PPT P5「调度与服务化整合」）：代理访问入口、专家库管理、运行节点编排、工作区配置库、工作数据留痕、规模任务调度。
**设计原则**：能用工具解决的不依赖模型；算力友好（路由/意图识别/范围圈定避免大海捞针）；大规模调度代码化。

## 4. 核心执行模型

### 4.1 节点类型（已确认五类，R3 维持不新增）

| 节点类型 | 关键配置 | 出边规则 |
|---|---|---|
| 开始 / 结束 | — | 流程边界 |
| 阶段分组 | 阶段名（如需求分析/方案设计/开发测试/集成验证）、阶段准出说明（PPT P1 评审准出） | 容器，组织子节点 |
| 专家执行节点 | 绑定专家；Skill 组合（默认继承专家，可增删）；Harness 分配（按标签自动 / 手动指定）；输入说明（读取工作区哪些路径）；输出约定（写入哪些路径/产物）；「上下文与收敛」配置（见 §4.5） | 顺序边 ×1（单一后继） |
| 评审/校验节点 | 绑定评审专家（独立否决视角）；评审要点；**固定回退目标节点（唯一）** | 通过 → 顺序边；不通过 → 回退边（固定目标） |
| 人工确认节点 | 确认事项/方案说明（Agent 先将方案写入工作区，人工在实例详情查看）；超时策略 | 批准 → 顺序边；驳回 → 建议允许固定驳回回退边（开放确认 §9） |
| fan-out 网关 | 任务清单来源（上游产物路径，如按调用链/模块/文件拆分）；分片规则；并发上限；子任务模板（绑定专家 + Skill + 独立 worktree/任务目录） | 展开为 N 个子任务 → fan-in |
| fan-in 网关 | 聚合策略：**全部完成 / 失败阈值 / 抽样人工审核**；汇聚产物写入路径 | 顺序边 ×1 |

> **R3 裁定说明**：意图路由、Re-act 循环、CI/CD 触发**均不设专门节点**。意图分流 = 入口专家节点 + 分支工作流配置扮演；循环 = 评审节点 + 回退边表达；CI/CD 集成为后续扩展（文档记录）。

### 4.2 回退机制（已确认：固定单一回退点）

- 编辑器中每个评审/校验节点预设**唯一**回退目标节点；不通过时编排器携带评审意见回到该节点重跑。
- 回退时评审意见写入工作区留痕，供回退节点读取（上下文仍隔离，经由 Workspace 传递）。
- 回退仅由评审节点**自动触发**，不做人工注入回退；回退次数上限暂不做（开放确认 §9）。

### 4.3 fan-out / fan-in（已确认：清单驱动 + 聚合策略）

- 上游节点产出任务清单（如按调用链/模块/文件级别拆分的审视任务），编排器代码化拆分并按**并发上限**调度。
- 每个子任务：独立上下文 + 独立 worktree/任务目录，结果写回工作区。
- fan-in 聚合策略：全部完成 / 失败阈值 / 抽样人工审核；聚合报告写入工作区后进入下一节点。
- 数千规模呈现：实例详情提供**聚合视图**（按状态分组统计 + 抽样明细列表），不逐条平铺。

### 4.4 实例状态机与控制（已确认）

- 实例状态：`排队 → 运行中 →（等待人工确认 | 回退重跑中 | 已暂停）→ 成功 / 失败 / 已终止`
- 节点状态：待执行 / 运行中 / 等待人工 / 成功 / 失败 / 已跳过 / 触发回退
- 子任务状态（fan-out）：待调度 / 运行中 / 成功 / 失败 / 重试中
- 控制操作（实例页）：**异常终止、暂停/恢复、节点重试、从指定节点重跑、节点输入输出与工作区留痕查看**
- 方案确认：由**人工确认节点**承载——实例挂起后，详情页展示待确认方案，提供批准/驳回（附意见）；列表用状态角标提示，无独立实例级审批面板。

### 4.5 节点级「上下文与收敛」配置（R3 采纳，评审节点外的通用配置分组）

| 配置项 | 说明 |
|---|---|
| 知识索引注入 | 配置节点运行期注入的分层知识索引范围（业务域 → 价值流 → 场景 → 代码入口）与 SVO 锚点，防止大海捞针与发散乱猜 |
| 收敛约束与上下文上限 | Harness 收敛条件、格式规范、上下文长度上限等约束配置展示（引擎裁剪逻辑不做，仅配置项与留痕展示） |
| 工具使用权限 | 限定该节点允许调用的 MCP/CLI 工具清单（引用「工具与集成」页注册的工具资产） |

## 6. 关键用户旅程（原型需可走通）

**旅程 A · 流程研发主线**：工作流列表 → 打开「研发四阶段主流程」编辑器（阶段分组 + 评审回退 + 人工确认 + 节点上下文配置 + DSL 视图）→ 发起运行 → 实例详情：节点依次运行 → 评审节点不通过 → 回退轨迹高亮 → 带意见重跑 → 通过 → 人工确认节点挂起 → 批准附意见 → 继续至成功 → 查看工作区留痕。

**旅程 B · 大规模并行**：打开「批量代码审视」工作流 → fan-out 网关按模块清单展开（模拟 2,000+ 子任务）→ 实例详情聚合视图（状态分组统计 + 抽样明细 + 失败重试）→ fan-in 按「失败阈值」聚合 → 汇总报告节点。

**旅程 C · 管理配置线**：注册 Harness（容器，能力标签）→ 注册工具（CLI/MCP）→ 新建工作区（绑定 git 仓库 + 关联 ssh-key + 目录模板初始化 + 连通性校验）→ 注册 Skill → 组合注册专家（配置知识索引注入与工具权限）→ 编辑器中绑定专家 → 发起运行。

**旅程 D · 运营回看**：效能看板查看吞吐率/缺陷率指标 → 下钻某阶段准出记录 → 查看 Skill 审计提示（如「某禁令被跳过 3 次」）。
