# 代码重构要点（本项目前端的防御性规则）

本文档沉淀本次开发与多轮修复中确立的编码规则。每条规则背后都对应一个真实发生过的缺陷（坑档案有对应条目），**改代码前先读本页**，评审时按本页逐条检查。

## 1. 事件绑定的作用域规则（最高频缺陷来源）

页面骨架由 `DF.renderShell` 生成：`#app` 内是顶部栏 + 布局区；布局区内 `.breadcrumb`、`.page-header`（内含标题与操作按钮容器 `.acts`）、`#page-body` 三者**互为兄弟节点**。由此产生三条硬规则：

1. **页头操作按钮必须用 `document.getElementById` 绑定**。用 `document.querySelector('#page-body').querySelector('#btn-new')` 这类以页面主体为根的查找永远找不到 `.acts` 里的按钮（它在主体之外），而且**失败是静默的**——按钮渲染正常、点击无反应、无任何报错。工作流列表页的「新建工作流」按钮曾因此完全失效。
2. **弹层/抽屉的页脚按钮必须以最近的容器为作用域绑定**。弹窗结构是 `.d-head` + `.d-body` + `.d-foot` 三兄弟，页脚按钮用 `body.querySelector('#xxx')` 查找会拿到 null 直接抛错（弹窗打开即崩）。标准写法：
   ```javascript
   const foot = b.closest('.modal').querySelector('.d-foot');   // 弹窗（b 为弹窗主体容器）
   const foot = d.closest('.drawer').querySelector('.d-foot');  // 抽屉
   ```
3. **同一 id 全文档唯一**。属性抽屉等内容动态注入的容器（如 `#we-inspector`）在关闭旧实例后才能创建新实例；用「`document.getElementById('we-inspector')` 是否存在」判断抽屉是否已打开，依赖的就是这条唯一性。

## 2. 函数拆分时的闭包变量断链

把「渲染 HTML」与「绑定行为」拆成两个函数（如 `agentInspector(n)` / `bindAgentInspector(n)`）时，**绑定函数不能引用渲染函数里的局部变量**——它们是平行函数，不是嵌套闭包。本次会话连续踩了两次同型缺陷（`doms`、`cur`）：渲染函数里 `const doms = MOCK.knowledgeTree`，绑定函数里直接用 `doms.find(...)`，运行到即抛 `ReferenceError`，且错误发生在事件回调里，只在用户触发特定交互时暴露（表现为「选中某类节点后拖拽失效」），`node --check` 完全查不出。

规则：**绑定函数自行获取所需数据**（自己 `MOCK.byId(...)` / 自己从节点配置里取值），或把共享数据提升为模块级常量。评审时专门检查两个平行函数之间有没有"顺手共用"的变量。

## 3. DOM 构建的次序：先 innerHTML，后 appendChild

对同一容器先 `appendChild` 再赋值 `innerHTML` 会把之前挂上去的节点**整体覆盖清除**。弹窗的拖宽把手曾因此消失（把手先挂、`innerHTML` 后赋值，把手被清掉，测试报"找不到把手"）。规则：容器内容的构建一律 `innerHTML` 在前，动态创建的节点（把手、拖拽提示等）在最后 `appendChild`。

## 4. 共享能力下沉到 ui.js，页面只传参

弹窗/抽屉的通用能力一律在 `assets/js/ui.js` 的 `DF.modal` / `DF.drawer` 实现，页面代码只传选项，禁止在页面里复制粘贴弹层管理逻辑。已下沉的能力清单（改造时扩展这里，不要另起炉灶）：

- `DF.modal.open`：`width` 支持数字（像素）或字符串（`'80vw'` 等，内部按当前缩放系数换算为视觉宽度）；`resizable: true` 启用左右拖宽把手（对称展开，范围钳制，双击恢复默认宽）；
- `DF.drawer.open`：`noOverlay: true` 表示不加暗色遮罩（用于"抽屉打开时背景仍需可操作"的场景，如编辑器属性抽屉）；
- `DF.modal.confirm`：Promise 化确认框，内部有 settled 标志防重复解析——不要在页面里再包一层自定义确认逻辑。
- `DF.menu(items, x, y, opts)`：右键/更多菜单（fixed 弹层，z-index 250）。调用方统一传**视觉坐标**（`clientX` 与 `rect` 均是视觉值），内部按缩放路径归一（zoom 路径除以 `zoomK`，兜底路径原样）；`opts.alignRight` 为锚定下拉语义：x 视作右缘坐标，量实际宽度反推 left（防溢出钳制 `innerWidth-160` 只作用于默认左缘语义，会破坏右缘锚定）——顶栏用户区下拉用此语义。

## 5. 引擎兼容的双路径模式（能力探测 → 主路径 + 兜底）

凡是依赖引擎特性的实现（当前是 CSS zoom 的字体缩放），必须按此模式写，禁止单路径硬编码：

1. **探测**：往页面里放一个已知尺寸的探针元素，实测渲染结果与期望是否一致（方法见《调试方案》第 5 节）；
2. **主路径**：探测生效走标准方案（html 级 zoom，连弹层一起缩放）；
3. **兜底**：探测失效走降级方案（对 `.topbar` 与 `#df-layout` 做 transform 缩放，弹层保持基准尺寸），并且**必须显式清除主路径已设置的属性**（zoom 残留会把 fixed 包含块搞坏）；
4. **数学归一集中在访问器后**：所有需要知道"当前实际缩放系数"的代码（弹层宽度换算、拖宽把手、画布坐标换算）一律调 `DF.zoomK()` / `DF.zoomOnFixed()`，不要各自缓存系数——否则两条路径下必有一条算错。

坐标换算同样收口：画布的视口坐标 → 图形坐标换算统一走 `toGraph()` / `clientDelta()`（`workflow-editor.js`），禁止在各个事件处理器里手写 `(clientX - r.left + scrollLeft) / state.zoom` 的变体——缩放模式一变，散落的公式必然漏改。

## 6. 重构流程：先锁行为，再动代码

1. **先写冒烟脚本锁定现状**（引擎层，按《调试方案》模板）：覆盖将被重构的交互路径，先跑通拿到基线；
2. 小步修改，每步过语法层检查（`node --check`）；
3. 重跑冒烟比对；行为变化要么是预期（更新断言并说明），要么是回归（回滚）；
4. 收尾跑全站回归循环（12 个页面 + 查询参数变体）；
5. 涉及新坑的，登记到 `docs/history/pitfalls.md`；确立新规则的，更新本文档。

## 7. 批量页面生成的经验（子代理协作）

- 给子代理的提示词**一页一份**，并把 `DF` 公共 API 速查表直接内嵌进提示词；一份提示词塞 2–3 个页面会耗尽子代理上下文，产不出任何文件。
- 页头按钮、弹层页脚这两类绑定缺陷在批量生成中成批出现（一次 5 个页面 9 处），生成后必须按第 1 节规则逐页检查。
- 工作量最大的两个页面（工作流编辑器、实例列表/详情）不值得走子代理，直接主笔。

## 8. 不要"顺手修"的产品决策（重构禁区）

以下是有意为之的现状，重构时保持，不要当缺陷处理：

- 模拟数据全部在内存（`MOCK`），刷新即重置——原型定位如此；
- 跨页临时传递用 sessionStorage 单键单值（`df-new-instance`、`df-new-workspace`）；
- 从失败节点重跑/重试是演示性 toast，不做真实执行；
- 回退次数上限、驳回后的回退边形态等开放问题未定稿（登记于 `plan/open-questions.md`，状态未领取），保持默认实现，不扩展。
